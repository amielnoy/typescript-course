חזרה: Encapsulation – האובייקט שומר על עצמו

כלימה הוא נותן
private / #fieldרק המחלקה עצמה ניגשת
protectedהמחלקה והבנות שלה
readonlyמציבים פעם אחת (בבנאי), קוראים תמיד
get / setגישה מבוקרת: ערך מחושב, ולידציה, נרמול
החוקים (מונים, ולידציה, סיסמאות) כתובים במקום אחד – ואי אפשר לעקוף אותם מבחוץ.
        class TestRun {
          #passed = 0;
          #failed = 0;
          constructor(readonly id: string) {}
          record(ok: boolean): void {
            if (ok) this.#passed++;
            else this.#failed++;
          }
          get passRate(): number {
            const total = this.#passed + this.#failed;
            if (total === 0) return 0;
            return Math.round((this.#passed / total) * 100);
          }
        }
        const run = new TestRun("nightly-42");
        [true, true, false].forEach((ok) => run.record(ok));
        console.log(`${run.id}: ${run.passRate}%`);
        // run.#passed = 100; ❌   run.id = "x"; ❌
      
        nightly-42: 67%

חזרה: Inheritance – extends, super, protected

  • extends – מחלקה בת מקבלת את כל מה שיש לאב
  • super(...) – קורא לבנאי של האב (חובה לפני this)
  • protected – נגיש באב ובבנות, לא מבחוץ
  • היום: מה קורה כשהבת משנה מתודה של האב – ולמה זה כל כך שימושי
ירושה = "is-a": UsersApi הוא BaseApi. בגלל זה אפשר להשתמש בו בכל מקום שמצפה ל-BaseApi.
        class BaseApi {
          constructor(protected baseUrl: string) {}
          url(path: string): string {
            return `${this.baseUrl}${path}`;
          }
        }
        class UsersApi extends BaseApi {
          constructor(baseUrl: string) {
            super(baseUrl); // קודם כל – האב
          }
          list(): string {
            return `GET ${this.url("/users")}`; // מתודה של האב
          }
        }
        console.log(new UsersApi("http://localhost:3000").list());
      
        GET http://localhost:3000/users

Polymorphism – רב-צורתיות

  • אותה קריאה – התנהגות שונה לפי הסוג האמיתי של האובייקט
  • הקוד שמשתמש באובייקטים מכיר רק את הטיפוס הכללי (מחלקת האב / הממשק)
  • ההחלטה איזה מימוש ירוץ מתקבלת בזמן ריצה
  • התוצאה: מוסיפים סוג חדש = מוסיפים מחלקה, בלי לשנות קוד קיים
  • באוטומציה: report.render(), page.isLoaded(), notifier.notify(), driver.click()

צעד 1: מחלקת בסיס ודריסה (override)

  • למחלקת הבסיס Notifier יש מימוש "כללי" של notify
  • EmailNotifier דורסת (override) את notify – אותו שם, אותה חתימה, גוף אחר
  • כשקוראים ל-notify על אובייקט Email – רץ המימוש של Email
  • המילה override אומרת לקומפיילר: "אני דורס בכוונה"
        class Notifier {
          constructor(protected recipient: string) {}
          notify(msg: string): string {
            return `[generic] to ${this.recipient}: ${msg}`;
          }
        }
        class EmailNotifier extends Notifier {
          override notify(msg: string): string {
            return `📧 Email to ${this.recipient}: ${msg}`;
          }
        }
        const email = new EmailNotifier("qa@example.com");
        console.log(email.notify("build passed"));
        console.log(new Notifier("ops").notify("build passed"));
      
        📧 Email to qa@example.com: build passed
        [generic] to ops: build passed

דוגמה: ערוצי התראה – עוד שתי מחלקות בנות

  • כל בת מממשת notify בדרכה
  • SlackNotifier צריכה שדה נוסף (channel) – ולכן בנאי משלה שקורא ל-super
  • SmsNotifier מקצרת הודעות ארוכות – לוגיקה שקיימת רק אצלה
  • הבסיס לא יודע ולא צריך לדעת על אף אחת מהן
      class SlackNotifier extends Notifier {
        constructor(recipient: string, private channel: string) {
          super(recipient);
        }
        override notify(msg: string): string {
          return `💬 Slack #${this.channel} @${this.recipient}: ${msg}`;
        }
      }

      class SmsNotifier extends Notifier {
        override notify(msg: string): string {
          const short =
            msg.length > 20 ? msg.slice(0, 17) + "..." : msg;
          return `📱 SMS to ${this.recipient}: ${short}`;
        }
      }

מערך מסוג מחלקת הבסיס

  • Notifier[] יכול להכיל כל אובייקט שהוא Notifier – כולל כל הבנות
  • על איברי המערך מותר לקרוא רק למה שמוגדר ב-Notifier
  • מתודה שקיימת רק בבת (joinChannel) – שגיאת קומפילציה
  • וגם הפוך: אי אפשר לשים אב במשתנה מסוג בת
זה בדיוק מה שאנחנו רוצים: הקוד הכללי עובד רק עם "החוזה" המשותף.
      class SlackNotifier extends Notifier {
        // ... notify כמו קודם
        joinChannel(): string {
          return `joined #${this.channel}`;
        }
      }

        new EmailNotifier("qa@x.io"),    // ✅ בת
        new SlackNotifier("dana", "qa"), // ✅ בת
      ];
      team[0].notify("hi");              // ✅ קיים ב-Notifier

      team[1].joinChannel();

      const s: SlackNotifier = new Notifier("x");

המילה override – הקומפיילר שומר עלינו

  • בפרויקט מוגדר noImplicitOverride: דריסה חייבת להיות מסומנת ב-override
  • היתרון: טעות הקלדה בשם המתודה או חתימה שונה – נתפסות לפני הרצת הבדיקות

❌ שכחנו override

        class A extends Notifier {
          notify(msg: string): string {
            return msg;
          }
        }
        // error TS4114: This member must have an
        // 'override' modifier because it overrides
        // a member in the base class 'Notifier'.

❌ טעות הקלדה

        class B extends Notifier {
          override notfy(msg: string): string {
            return msg;
          }
        }
        // error TS4117: This member cannot have an
        // 'override' modifier because it is not
        // declared in the base class 'Notifier'.
        // Did you mean 'notify'?
נכון: override notify(msg: string): string { ... } – אותו שם, אותם פרמטרים, אותו טיפוס החזרה.

super.method() – להרחיב במקום להחליף

  • לפעמים לא רוצים להחליף את התנהגות האב, אלא להוסיף לה
  • super.log(...) קורא למימוש של האב מתוך המתודה הדורסת
  • הפורמט [STEP] כתוב פעם אחת – אם ישתנה, ישתנה לכולם
  • אפשר להוסיף לפני (TimedLogger) או לשנות את הקלט (ApiLogger)
בלי super היינו מעתיקים את `[STEP] ...` לכל בת – שכפול קוד.
        class StepLogger {
          log(step: string): string { return `[STEP] ${step}`; }
        }
        class TimedLogger extends StepLogger {
          override log(step: string): string {
            return `10:42:07 ${super.log(step)}`;
          }
        }
        class ApiLogger extends StepLogger {
          override log(step: string): string {
            return super.log(`[api] ${step}`);
          }
        }
        const loggers: StepLogger[] =
          [new StepLogger(), new TimedLogger(), new ApiLogger()];
        loggers.forEach((l) => console.log(l.log("open login")));
      
        [STEP] open login
        10:42:07 [STEP] open login
        [STEP] [api] open login

instanceof – לבדוק מה הסוג האמיתי

  • x instanceof C מחזיר true אם x נוצר מ-C או מבת של C
  • בתוך ה-if – TypeScript "מצמצם" (narrowing) את הטיפוס, ואפשר לקרוא למתודות של הבת
  • כן: בדיקת שגיאות ב-catch – err instanceof Error, או פעולה חד-פעמית שקיימת רק בבת
לא: שרשרת if (n instanceof ...) שבוחרת "איך לעשות" – זה ה-if על הסוג מהשקף הקודם, בתחפושת. תנו לאובייקט להחליט: n.notify(msg).
        for (const x of team) {
          if (x instanceof SlackNotifier) {
            console.log(x.joinChannel()); // ✅ x: SlackNotifier
          }
        }
        const e = new EmailNotifier("a@b.c");
        console.log(e instanceof EmailNotifier,
          e instanceof Notifier, e instanceof SlackNotifier);
        try {
          JSON.parse("{bad json");
        } catch (err) {
          if (err instanceof Error) {
            console.log("Parse failed:", err.name);
          }
        }

        true true false

סיכום

  • Encapsulation: private / # / readonly + getters/setters – האובייקט שומר על התקינות של עצמו
  • Inheritance: extends + super(...) – קוד משותף נכתב פעם אחת, protected לבנות בלבד
  • Polymorphism: קוד שעובד מול טיפוס כללי, והמימוש נבחר בזמן ריצה
  • override + noImplicitOverride שומרים על דריסות נכונות · super.method() מרחיב במקום להחליף
