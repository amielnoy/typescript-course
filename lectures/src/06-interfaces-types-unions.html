Interfaces – ממשקים

חוזה שמתאר את הצורה של אובייקט · examples/01-interfaces.ts

Interface – תיאור הצורה של אובייקט

  • חוזה: אילו שדות חייבים להיות ומה הטיפוס שלהם
  • קיים רק בזמן קומפילציה – אין לו קוד, ואין לו קיום בזמן ריצה
  • ? אופציונלי · readonly לקריאה בלבד
  • extends – הרחבת ממשק
  • מושלם לתיאור תשובות API ונתוני בדיקה
        interface Customer {
          readonly id: number;      // לא ניתן לשינוי
          fullName: string;
          email: string;
          loyaltyPoints?: number;   // אופציונלי
        }

        const noa: Customer = {
          id: 1, fullName: "Noa Levi", email: "noa@shop.dev",
        };
        // noa.id = 2;                                ❌ readonly
        // const bad: Customer = { id: 2, fullName: "x" };  ❌ missing email
        console.log("Customer:", noa);

        interface BusinessCustomer extends Customer {
          companyId: string;
        }
      
        Customer: { id: 1, fullName: 'Noa Levi', email: 'noa@shop.dev' }

למה זה חשוב? ארבע טעויות שהקומפיילר תופס מיד

    const a: Customer = { id: 2, fullName: "x" };                                // 1. missing required field
    // ❌ Property 'email' is missing in type '{ id: number; fullName: string; }' but required in type 'Customer'.

    const b: Customer = { id: 3, fullName: "Omer", email: "o@shop.dev", age: 30 }; // 2. field not in the contract
    // ❌ Object literal may only specify known properties, and 'age' does not exist in type 'Customer'.

    const c: Customer = { id: "4", fullName: "Omer", email: "o@shop.dev" };       // 3. wrong field type
    // ❌ Type 'string' is not assignable to type 'number'.

    function greet(c: Customer) { return `Hi ${c.fulName}`; }                      // 4. typo in a field name
    // ❌ Property 'fulName' does not exist on type 'Customer'. Did you mean 'fullName'?
  • כל שורה כאן לא מתקמפלת – npx tsc --noEmit מדפיס בדיוק את ההודעות האלה
  • איך קוראים הודעה: "Type X is not assignable to type Y" = "נתת X, אבל החוזה דורש Y"
  • ועם any? אותה שגיאת כתיב (c: any ו-c.fulName) מתקמפלת, רצה ומדפיסה Hi undefined – והבאג מגיע לדוח
טיפוסים הם "בדיקה" שרצה על קוד הבדיקות עצמו – וב-VS Code רואים אותה מיד בקו האדום, בלי להריץ כלום.

שדות אופציונליים – ?

  • loyaltyPoints?: number = השדה יכול לא להופיע
  • הטיפוס שלו בפועל: number | undefined
  • לכן TS מחייב לבדוק אותו לפני שימוש
  • דרכים לטפל: if, או ברירת מחדל עם ??
  • שימושי לשדות שהשרת מחזיר רק לפעמים
כאן בודקים !== undefined ולא if (c.loyaltyPoints): גם 0 נקודות הוא ערך תקין, אבל הוא falsy.
        function pointsLine(c: Customer): string {
          // return c.loyaltyPoints.toFixed(0);
          // ❌ 'c.loyaltyPoints' is possibly 'undefined'.
          if (c.loyaltyPoints !== undefined) {
            return `${c.fullName}: ${c.loyaltyPoints} pts`;
          }
          return `${c.fullName}: (not in the club)`;
        }
        console.log(pointsLine(noa));
        console.log(pointsLine({ ...noa, loyaltyPoints: 120 }));
        console.log(noa.loyaltyPoints ?? 0);
      
        Noa Levi: (not in the club)
        Noa Levi: 120 pts
        0

readonly – לקריאה בלבד

  • שדה שנקבע פעם אחת ולא משתנה: cartId שהשרת יצר
  • readonly string[] – גם המערך עצמו לא ניתן לשינוי (אין push)
  • שדה רגיל (itemCount) – מותר לשנות
ההגנה היא בזמן קומפילציה בלבד – ב-JavaScript שנוצר אין שום נעילה.
        interface Cart {
          readonly cartId: string;
          readonly couponCodes: readonly string[];
          itemCount: number;
        }
        const cart: Cart = {
          cartId: "C-301", couponCodes: ["WELCOME10"], itemCount: 2,
        };
        cart.itemCount = 3;     // ✅ מותר

        cart.cartId = "C-302";
        // ❌ Cannot assign to 'cartId' because it is a read-only property.
        cart.couponCodes.push("FREESHIP");
        // ❌ Property 'push' does not exist on type 'readonly string[]'.

        console.log(cart);
      
        { cartId: 'C-301', couponCodes: [ 'WELCOME10' ], itemCount: 3 }

Interface לתשובת API

  • מתארים את ה-JSON פעם אחת – ומקבלים השלמה אוטומטית בכל הבדיקות
  • interface יכול להכיל interface אחר, מערכים ואובייקטים מקוננים
  • טעות בשם שדה נתפסת – כולל הצעה לתיקון
JSON.parse מחזיר any: הטיפוס הוא הבטחה שלנו, לא בדיקה. בדיקה אמיתית בזמן ריצה – type guard (חלק 3).
        interface CatalogItemDto {
          sku: string;
          title: string;
          priceCents: number;
        }
        interface SearchPage {
          items: CatalogItemDto[];
          paging: { page: number; totalItems: number };
        }
        const body: SearchPage = JSON.parse(raw); // raw = response body (text)
        console.log(body.paging.totalItems, body.items.map((i) => i.title));

        body.items[0].titel;
        // ❌ Property 'titel' does not exist on type 'CatalogItemDto'.
        //    Did you mean 'title'?
      
        2 [ 'Mug', 'T-shirt' ]

Interface לנתוני בדיקה (Data-Driven)

  • טבלת מקרי בדיקה = מערך של אובייקטים מאותה צורה: SignupCase[]
  • שכחתם שדה במקרה ה-20? הקומפיילר יגיד לכם איפה
  • שדה אופציונלי (expectError?) מבדיל בין מקרה חיובי לשלילי
אותו interface משמש גם את הנתונים וגם את הפונקציה שמריצה אותם.
        interface SignupCase {
          title: string;
          email: string;
          password: string;
          expectError?: string;
        }
        const cases: SignupCase[] = [
          { title: "valid signup", email: "omer@shop.dev",
            password: "Str0ng!pass" },
          { title: "short password", email: "omer@shop.dev",
            password: "123", expectError: "Password too short" },
          { title: "bad email", email: "omer.shop.dev",
            password: "Str0ng!pass", expectError: "Invalid email" },
        ];
        for (const c of cases) {
          const expected = c.expectError ?? "account created";
          console.log(`${c.title.padEnd(15)} -> ${expected}`);
        }
      
        valid signup    -> account created
        short password  -> Password too short
        bad email       -> Invalid email

Index signature – מפתחות שלא ידועים מראש

  • [flag: string]: boolean – "כל מפתח מסוג string, וכל ערך boolean"
  • מתאים ל-feature flags, שגיאות ולידציה, headers, query params
  • Record<string, string> – אותו רעיון בכתיב קצר
  • גם הערך נבדק: מספר במקום boolean – שגיאה
מפתח שלא קיים מחזיר undefined בזמן ריצה – אף שהטיפוס אומר boolean.
        interface FeatureFlags {
          [flag: string]: boolean;
        }
        const flags: FeatureFlags = { "new-checkout": true };
        flags["dark-mode"] = false;
        console.log(Object.keys(flags), flags["beta-search"]);
        // flags["max-items"] = 50;
        // ❌ Type 'number' is not assignable to type 'boolean'.

        interface ProblemDetails {
          status: number;
          title: string;
          errors?: Record<string, string>; // מילון
        }
        const problem: ProblemDetails = { status: 422, title: "Unprocessable",
          errors: { zip: "must be 7 digits" } };
        console.log(`${problem.status} ${problem.title}`, problem.errors);
      
        [ 'new-checkout', 'dark-mode' ] undefined
        422 Unprocessable { zip: 'must be 7 digits' }

extends – הרחבת ממשק

  • BusinessCustomer מקבל את כל השדות של Customer + שדות משלו
  • BusinessCustomer הוא גם Customer – אפשר להעביר אותו לכל פונקציה שמצפה ל-Customer
  • אפשר להרחיב כמה ממשקים בבת אחת: extends A, B
  • שימוש בבדיקות: ApiError בסיסי ו-ValidationError שמוסיף שדות
        interface BusinessCustomer extends Customer {
          companyId: string;
          seats: number;
        }
        const acme: BusinessCustomer = {
          id: 2, fullName: "Acme Ltd", email: "it@acme.dev",
          companyId: "51-123", seats: 40,
        };
        function greet(c: Customer): string { return `Hi ${c.fullName}`; }
        console.log("Seats:", acme.seats);
        console.log(greet(acme));   // a BusinessCustomer is also a Customer
        interface Verified { verifiedAt: string; }
        interface VerifiedBusiness extends BusinessCustomer, Verified {}
        const verified: VerifiedBusiness =
          { ...acme, verifiedAt: "2026-11-24" };
        console.log(Object.keys(verified));

        Hi Acme Ltd
        [ 'id', 'fullName', 'email', 'companyId', 'seats', 'verifiedAt' ]

implements – מחלקה שמתחייבת לחוזה

  • interface יכול לתאר גם מתודות, לא רק שדות
  • implements – הקומפיילר בודק שהמחלקה מימשה הכול
  • כל מחלקה מממשת אחרת: אחת מדפיסה, אחת שומרת בזיכרון
  • שכחתם מתודה? שגיאה כבר בשורת ה-class
דוגמה מהעולם שלנו: איפה שומרים "ארטיפקטים" של בדיקה שנכשלה – לוג, HTML, צילום מסך.
        interface ArtifactStore {
          save(name: string, content: string): void;
          list(): string[];
        }
        class ConsoleStore implements ArtifactStore {
          save(name: string, content: string) {
            console.log(`💾 ${name} (${content.length} chars)`);
          }
          list() { return []; }   // prints only
        }
        class MemoryStore implements ArtifactStore {
          private files = new Map<string, string>();
          save(name: string, content: string) {
            this.files.set(name, content);
          }
          list() { return [...this.files.keys()]; }
        }

        class HalfStore implements ArtifactStore {
          save(name: string, content: string) { console.log(name); }
        }
        // ❌ Class 'HalfStore' incorrectly implements
        //    interface 'ArtifactStore'. Property 'list' is missing
        //    in type 'HalfStore' but required in type 'ArtifactStore'.

תלוי בחוזה, לא במימוש – Structural typing

  • saveFailure מקבלת כל ArtifactStore – פולימורפיזם דרך ממשק, בלי הורשה
  • MemoryStore מצוין לבדיקות של התשתית עצמה: אפשר לבדוק מה נשמר
  • TS בודק צורה, לא שם: כל אובייקט עם save + list מתאים – גם בלי class ו-implements ("Duck typing")
  • שימושי מאוד ליצירת אובייקטים מזויפים (fakes) בבדיקות
אז למה בכלל implements? כדי שהשגיאה תופיע במחלקה עצמה, ולא רק במקום שבו משתמשים בה.
        function saveFailure(store: ArtifactStore, test: string): void {
          store.save(`${test}.log`, "Timeout after 5000ms");
          store.save(`${test}.html`, "<html>...</html>");
        }
        saveFailure(new ConsoleStore(), "checkout");
        const mem = new MemoryStore();      // great for testing the framework
        saveFailure(mem, "checkout");
        console.log(mem.list());
        const inlineStore = {               // no class, no implements
          save: (name: string, content: string) =>
            console.log("inline:", name, content.length),
          list: () => [] as string[],
        };
        saveFailure(inlineStore, "login");  // ✅ fits ArtifactStore
      
        💾 checkout.log (20 chars)
        💾 checkout.html (16 chars)
        [ 'checkout.log', 'checkout.html' ]
        inline: login.log 20
        inline: login.html 16

מחלקה יכולה לממש כמה ממשקים

  • implements Connectable, Resettable – מתחייבת לשני החוזים
  • בניגוד ל-extends של מחלקות (רק הורה אחד) – ממשקים אפשר לממש כמה שרוצים
  • כל פונקציה רואה רק את ה"חלק" שמעניין אותה: beforeEachTest רואה רק reset()
ממשקים קטנים וממוקדים (Connectable, Resettable) קלים יותר לשימוש חוזר.
        interface Connectable {
          connect(): void;
        }
        interface Resettable {
          reset(): void;
        }
        class DbFixture implements Connectable, Resettable {
          connect() { console.log("[db] connected"); }
          reset() { console.log("[db] tables truncated"); }
        }

        function beforeEachTest(resource: Resettable): void {
          resource.reset();
        }
        const db = new DbFixture();
        db.connect();
        beforeEachTest(db);
      
        [db] connected
        [db] tables truncated

טעויות נפוצות – Interfaces

❌ any לתשובה – אין הגנה

        const body: any = await res.json();
        body.items[0].titel;   // undefined, no warning

✅ טיפוס לתשובה

        const body: SearchPage = await res.json();
        body.items[0].title;   // autocomplete + checked

❌ instanceof על interface

        if (x instanceof ArtifactStore) { }
        // ❌ 'ArtifactStore' only refers to a type,
        //    but is being used as a value here.

✅ interface לא קיים בזמן ריצה

        if (x instanceof MemoryStore) { }  // a class
        if ("save" in x) { }  // field check (part 3)
ושוב: שדה אופציונלי (?) – תמיד לבדוק או לתת ברירת מחדל עם ?? לפני שימוש.

Type Aliases – שמות לטיפוסים

literal types, tuple, intersection (&) ו-Utility Types · examples/02-type-aliases.ts

type – שם לכל טיפוס

  • type נותן שם לטיפוס – כל טיפוס: פרימיטיבי, אובייקט, פונקציה
  • price: Cents אומר יותר מ-price: number – מיד ברור שזה באגורות
  • טיפוס פונקציה: מגדירים פעם אחת את החתימה, ו-TS מסיק את הפרמטרים
alias הוא רק שם נוסף: Cents ו-number הם אותו טיפוס – והבדיקה היא של number.
        type Sku = string;
        type Cents = number;
        type Percent = number;
        type GeoPoint = { lat: number; lng: number };      // אובייקט
        type Validator = (value: string) => boolean;       // פונקציה

        function priceAfter(sku: Sku, price: Cents, off: Percent) {
          const final = Math.round((price * (100 - off)) / 100);
          return `${sku}: ${price} -> ${final} cents`;
        }
        const telAviv: GeoPoint = { lat: 32.08, lng: 34.78 };
        const isEmail: Validator = (v) => v.includes("@");  // v: string

        console.log(priceAfter("MUG-01", 4990, 20));
        console.log("Mock location", telAviv, isEmail("noa.shop.dev"));

        const price: Cents = "49.90";
        // ❌ Type 'string' is not assignable to type 'number'.
      
        MUG-01: 4990 -> 3992 cents
        Mock location { lat: 32.08, lng: 34.78 } false

Literal types – רק ערכים מסוימים מותרים

  • טיפוס יכול להיות ערך מדויק: "warn", 200, true
  • איחוד של literals עם | = רשימה סגורה של ערכים חוקיים
  • טעות כתיב נתפסת מיד – גם הבדל של אות גדולה/קטנה
  • VS Code משלים אוטומטית את האפשרויות
מתאים ל: רמות לוג, שפות, סביבות, שיטות HTTP, סטטוסים של טסט, רמות חומרה.
        type LogLevel = "debug" | "info" | "warn" | "error";
        type Locale = "he-IL" | "en-US" | "ar-IL";

        function log(level: LogLevel, msg: string): string {
          return `[${level.toUpperCase()}] ${msg}`;
        }
        console.log(log("warn", "Low stock: MUG-01"));
        console.log(log("error", "Payment declined"));

        log("fatal", "x");     // טעות נתפסת מיד
        // ❌ Argument of type '"fatal"' is not assignable
        //    to parameter of type 'LogLevel'.
        log("Info", "x");
        // ❌ Argument of type '"Info"' is not assignable
        //    to parameter of type 'LogLevel'.
      
        [WARN] Low stock: MUG-01
        [ERROR] Payment declined

מלכודת נפוצה: let "מרחיב" ל-string

הצהרההטיפוס ש-TS מסיק
let level = "info"string (אפשר לשנות לכל מחרוזת)
const level = "info""info" (לא ישתנה לעולם)
let level: LogLevel = "info"LogLevel
  • let בלי טיפוס = "מחרוזת כלשהי" – ולכן לא מתאים ל-LogLevel
  • הפתרון: const, או טיפוס מפורש
        let level = "info";
        log(level, "x");
        // ❌ Argument of type 'string' is not
        //    assignable to parameter of type 'LogLevel'.

        const l2 = "info";             // ✅ type is "info"
        let l3: LogLevel = "info";     // ✅ explicit type
        l3 = "debug";                  // ✅ still LogLevel
        console.log(log(l2, "a"), log(l3, "b"));

        l3 = "trace";
        // ❌ Type '"trace"' is not assignable
        //    to type 'LogLevel'.
      
        [INFO] a [DEBUG] b

Union של literals + Record – מילון שלם

  • Record<Locale, string> = אובייקט עם בדיוק מפתח לכל שפה
  • שכחתם שפה? שגיאה. הוספתם מפתח שלא קיים? שגיאה
  • הוספתם "ru-RU" ל-Locale? TS יראה לכם כל מקום שצריך לעדכן
מושלם לבדיקות לוקליזציה: לכל שפה – הפורמט שהמסך אמור להציג.
        const dateFormats: Record<Locale, string> = {
          "he-IL": "dd/mm/yyyy",
          "en-US": "mm/dd/yyyy",
          "ar-IL": "dd/mm/yyyy",
        };
        function dateFormatFor(locale: Locale): string {
          return `${locale}: ${dateFormats[locale]}`;
        }
        console.log(dateFormatFor("en-US"));
        const locales: Locale[] = ["he-IL", "en-US", "ar-IL"];
        console.log(locales.map(dateFormatFor).join(" | "));

        const f2: Record<Locale, string> = {
          "he-IL": "dd/mm/yyyy", "en-US": "mm/dd/yyyy" };
        // ❌ Property '"ar-IL"' is missing in type
        //    '{ "he-IL": string; "en-US": string; }'
        //    but required in type 'Record<Locale, string>'.
      
        en-US: mm/dd/yyyy
        he-IL: dd/mm/yyyy | en-US: mm/dd/yyyy | ar-IL: dd/mm/yyyy

Tuple – מערך באורך וסדר קבועים

  • [min: number, max: number] – בדיוק 2 איברים, בסדר הזה
  • השמות (min, max) רק לתיעוד – מופיעים בהשלמה האוטומטית

implements – עם interface וגם עם type

  • מחלקה יכולה לממש type – כל עוד הוא צורת אובייקט
  • union אי אפשר לממש: מחלקה לא יכולה להיות "זה או זה"
  • ולהפך: interface לא יכול להיות union / literal / tuple
        type Tier =
          "basic" | "gold" | "platinum";
        // interface Tier = ...  ❌
      
        class Shopper implements ShopperI {
          constructor(public name: string) {}
        }
        class VipShopper implements VipT {       // a type works too
          constructor(public name: string, public tier: number) {}
        }
        const t: Tier = "gold";
        console.log({ t, shopper: new Shopper("Omer"),
          vip: new VipShopper("Noa", 3) });

        class Bad implements Tier {}
        // ❌ A class can only implement an object type or intersection
        //    of object types with statically known members.
      
        {
          t: 'gold',
          shopper: Shopper { name: 'Omer' },
          vip: VipShopper { name: 'Noa', tier: 3 }
        }

סיכום

  • interface – חוזה לצורת אובייקט · implements – מחלקה מתחייבת לחוזה
  • type – שם לטיפוס, literal types, &, tuples · Utility types
  • Union + Narrowing – עבודה בטוחה עם ערכים מכמה סוגים
  • Discriminated unions + never – אף מקרה לא נשכח
  • הקומפיילר הוא "בודק" נוסף: טעויות כתיב, שדות חסרים ו-null נתפסים לפני הריצה
