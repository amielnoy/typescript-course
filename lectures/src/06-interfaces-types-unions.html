Interfaces – ממשקים

חוזה שמתאר את הצורה של אובייקט · examples/01-interfaces.ts

Interface – תיאור הצורה של אובייקט

  • חוזה: אילו שדות חייבים להיות ומה הטיפוס שלהם
  • קיים רק בזמן קומפילציה – אין לו קוד, ואין לו קיום בזמן ריצה
  • ? אופציונלי · readonly לקריאה בלבד
  • extends – הרחבת ממשק
  • מושלם לתיאור תשובות API ונתוני בדיקה
        interface User {
          readonly id: number;    // לא ניתן לשינוי
          name: string;
          email: string;
          phone?: string;         // אופציונלי
        }

        const dana: User = { id: 1, name: "Dana", email: "dana@example.com" };
        // dana.id = 2;                          ❌ readonly
        // const bad: User = { id: 2, name: "x" };  ❌ missing email
        console.log("User:", dana);

        interface Admin extends User {
          permissions: string[];
        }
      
        User: { id: 1, name: 'Dana', email: 'dana@example.com' }

למה זה חשוב? ארבע טעויות שהקומפיילר תופס מיד

    const a: User = { id: 2, name: "x" };                               // 1. missing required field
    // ❌ Property 'email' is missing in type '{ id: number; name: string; }' but required in type 'User'.

    const b: User = { id: 3, name: "Noa", email: "n@qa.io", age: 30 };  // 2. field not in the contract
    // ❌ Object literal may only specify known properties, and 'age' does not exist in type 'User'.

    const c: User = { id: "4", name: "Noa", email: "n@qa.io" };         // 3. wrong field type
    // ❌ Type 'string' is not assignable to type 'number'.

    function welcome(user: User) { return `Hi ${user.nmae}`; }          // 4. typo in a field name
    // ❌ Property 'nmae' does not exist on type 'User'.
  • כל שורה כאן לא מתקמפלת – npx tsc --noEmit מדפיס בדיוק את ההודעות האלה
  • איך קוראים הודעה: "Type X is not assignable to type Y" = "נתת X, אבל החוזה דורש Y"
  • ועם any? אותה שגיאת כתיב (user: any ו-user.nmae) מתקמפלת, רצה ומדפיסה Hi undefined – והבאג מגיע לדוח
טיפוסים הם "בדיקה" שרצה על קוד הבדיקות עצמו – וב-VS Code רואים אותה מיד בקו האדום, בלי להריץ כלום.

שדות אופציונליים – ?

  • phone?: string = השדה יכול לא להופיע
  • הטיפוס שלו בפועל: string | undefined
  • לכן TS מחייב לבדוק אותו לפני שימוש
  • דרכים לטפל: if, או ברירת מחדל עם ??
  • שימושי לשדות שהשרת מחזיר רק לפעמים
        function contactLine(user: User): string {
          // return user.phone.trim();
          // ❌ 'user.phone' is possibly 'undefined'.
          if (user.phone) {
            return `${user.name}: ${user.phone}`;
          }
          return `${user.name}: (no phone)`;
        }
        console.log(contactLine(dana));
        console.log(contactLine({ ...dana, phone: "050-1234567" }));
        console.log(dana.phone ?? "N/A");
      
        Dana: (no phone)
        Dana: 050-1234567
        N/A

readonly – לקריאה בלבד

  • שדה שנקבע פעם אחת ולא משתנה: id מהשרת, מזהה ריצה
  • readonly string[] – גם המערך עצמו לא ניתן לשינוי (אין push)
  • שדה רגיל (status) – מותר לשנות
ההגנה היא בזמן קומפילציה בלבד – ב-JavaScript שנוצר אין שום נעילה.
        interface TestRun {
          readonly runId: string;
          readonly tags: readonly string[];
          status: string;
        }
        const run: TestRun = {
          runId: "R-17", tags: ["smoke"], status: "running",
        };
        run.status = "done";     // ✅ מותר

        run.runId = "R-18";
        // ❌ Cannot assign to 'runId' because it is a read-only property.
        run.tags.push("ui");
        // ❌ Property 'push' does not exist on type 'readonly string[]'.

        console.log(run);
      
        { runId: 'R-17', tags: [ 'smoke' ], status: 'done' }

Interface לתשובת API

  • מתארים את ה-JSON פעם אחת – ומקבלים השלמה אוטומטית בכל הבדיקות
  • interface יכול להכיל interface אחר, מערכים ואובייקטים מקוננים
  • טעות בשם שדה נתפסת – כולל הצעה לתיקון
JSON.parse מחזיר any: הטיפוס הוא הבטחה שלנו, לא בדיקה. בדיקה אמיתית בזמן ריצה – type guard (חלק 3).
        interface UserDto {
          id: number;
          name: string;
          email: string;
        }
        interface UsersPage {
          data: UserDto[];
          meta: { page: number; total: number };
        }
        const body: UsersPage = JSON.parse(raw); // raw = response body (text)
        console.log(body.meta.total, body.data.map((u) => u.name));

        body.data[0].mail;
        // ❌ Property 'mail' does not exist on type 'UserDto'.
        //    Did you mean 'email'?
      
        2 [ 'Dana', 'Avi' ]

Interface לנתוני בדיקה (Data-Driven)

  • טבלת מקרי בדיקה = מערך של אובייקטים מאותה צורה: LoginCase[]
  • שכחתם שדה במקרה ה-20? הקומפיילר יגיד לכם איפה
  • שדה אופציונלי (expectError?) מבדיל בין מקרה חיובי לשלילי
אותו interface משמש גם את הנתונים וגם את הפונקציה שמריצה אותם.
        interface LoginCase {
          title: string;
          username: string;
          password: string;
          expectError?: string;
        }
        const cases: LoginCase[] = [
          { title: "valid user", username: "dana", password: "Secret1!" },
          { title: "wrong password", username: "dana", password: "x",
            expectError: "Invalid credentials" },
          { title: "empty username", username: "", password: "x",
            expectError: "Username is required" },
        ];
        for (const c of cases) {
          const expected = c.expectError ?? "login succeeds";
          console.log(`${c.title.padEnd(15)} -> ${expected}`);
        }
      
        valid user      -> login succeeds
        wrong password  -> Invalid credentials
        empty username  -> Username is required

Index signature – מפתחות שלא ידועים מראש

  • [name: string]: string – "כל מפתח מסוג string, וכל ערך string"
  • מתאים ל-headers, שגיאות ולידציה, query params
  • Record<string, string> – אותו דבר בכתיב קצר
  • גם הערך נבדק: מספר במקום מחרוזת – שגיאה
מפתח שלא קיים מחזיר undefined בזמן ריצה – אף שהטיפוס אומר string.
        interface HttpHeaders {
          [name: string]: string;
        }
        const headers: HttpHeaders = { "content-type": "application/json" };
        headers["x-request-id"] = "abc-123";
        console.log(Object.keys(headers), headers["x-trace"]);
        // headers["retries"] = 3;
        // ❌ Type 'number' is not assignable to type 'string'.

        interface ApiError {
          status: number;
          message: string;
          details?: Record<string, string>; // מילון
        }
        const err: ApiError = { status: 400, message: "Validation failed",
          details: { email: "is required" } };
        console.log(`Error ${err.status}: ${err.message}`, err.details);
      
        [ 'content-type', 'x-request-id' ] undefined
        Error 400: Validation failed { email: 'is required' }

extends – הרחבת ממשק

  • Admin מקבל את כל השדות של User + שדות משלו
  • Admin הוא גם User – אפשר להעביר אותו לכל פונקציה שמצפה ל-User
  • אפשר להרחיב כמה ממשקים בבת אחת: extends A, B
  • שימוש בבדיקות: ApiError בסיסי ו-ValidationError שמוסיף שדות
        interface Admin extends User {
          permissions: string[];
        }
        const admin: Admin = {
          id: 2, name: "Avi", email: "avi@example.com",
          permissions: ["delete-users"],
        };
        function welcome(user: User): string {
          return `Hi ${user.name}`;
        }
        console.log("Admin permissions:", admin.permissions);
        console.log(welcome(admin));   // an Admin is also a User

        interface Timestamped { createdAt: string; }
        interface AuditedAdmin extends Admin, Timestamped {}
        const audited: AuditedAdmin = { ...admin, createdAt: "2026-11-24" };
        console.log(Object.keys(audited));
      
        Admin permissions: [ 'delete-users' ]
        Hi Avi
        [ 'id', 'name', 'email', 'permissions', 'createdAt' ]

implements – מחלקה שמתחייבת לחוזה

  • interface יכול לתאר גם מתודות, לא רק שדות
  • implements – הקומפיילר בודק שהמחלקה מימשה הכול
  • כל מחלקה מממשת אחרת: אחת מדפיסה, אחת שומרת בזיכרון
  • שכחתם מתודה? שגיאה כבר בשורת ה-class
        interface Logger {
          info(message: string): void;
          error(message: string): void;
        }
        class ConsoleLogger implements Logger {
          info(message: string) { console.log(`ℹ️  ${message}`); }
          error(message: string) { console.log(`❌ ${message}`); }
        }
        class MemoryLogger implements Logger {
          readonly lines: string[] = [];
          info(message: string) { this.lines.push(`INFO ${message}`); }
          error(message: string) { this.lines.push(`ERROR ${message}`); }
        }

        class HalfLogger implements Logger {
          info(message: string) { console.log(message); }
        }
        // ❌ Class 'HalfLogger' incorrectly implements interface 'Logger'.
        //    Property 'error' is missing in type 'HalfLogger'
        //    but required in type 'Logger'.

תלוי בחוזה, לא במימוש – Structural typing

  • runSmokeTest מקבלת כל Logger – פולימורפיזם דרך ממשק, בלי הורשה
  • MemoryLogger מצוין לבדיקות של התשתית עצמה: אפשר לבדוק מה נרשם
  • TS בודק צורה, לא שם: כל אובייקט עם info + error מתאים – גם בלי class ו-implements ("Duck typing")
  • שימושי מאוד ליצירת אובייקטים מזויפים (fakes) בבדיקות
אז למה בכלל implements? כדי שהשגיאה תופיע במחלקה עצמה, ולא רק במקום שבו משתמשים בה.
        function runSmokeTest(logger: Logger): void {
          logger.info("Opening home page");
          logger.error("Logo not found");
        }
        runSmokeTest(new ConsoleLogger());
        const mem = new MemoryLogger();   // great for testing the framework
        runSmokeTest(mem);
        console.log(mem.lines);
        const inlineLogger = {            // no class, no implements
          info: (m: string) => console.log("inline:", m),
          error: (m: string) => console.log("inline ERR:", m),
        };
        runSmokeTest(inlineLogger);   // ✅ fits Logger
      
        ℹ️  Opening home page
        ❌ Logo not found
        [ 'INFO Opening home page', 'ERROR Logo not found' ]
        inline: Opening home page
        inline ERR: Logo not found

מחלקה יכולה לממש כמה ממשקים

  • implements Logger, Closable – מתחייבת לשני החוזים
  • בניגוד ל-extends של מחלקות (רק הורה אחד) – ממשקים אפשר לממש כמה שרוצים
  • כל פונקציה רואה רק את ה"חלק" שמעניין אותה: finish רואה רק close()
ממשקים קטנים וממוקדים (Logger, Closable) קלים יותר לשימוש חוזר.
        interface Closable {
          close(): void;
        }
        class BrowserSession implements Logger, Closable {
          info(m: string) { console.log(`[browser] ${m}`); }
          error(m: string) { console.log(`[browser] ERROR ${m}`); }
          close() { console.log("[browser] closed"); }
        }

        function finish(resource: Closable): void {
          resource.close();
        }
        const session = new BrowserSession();
        session.info("started");
        finish(session);
      
        [browser] started
        [browser] closed

טעויות נפוצות – Interfaces

❌ any לתשובה – אין הגנה

        const body: any = await res.json();
        body.data[0].mail;   // undefined, no warning

✅ טיפוס לתשובה

        const body: UsersPage = await res.json();
        body.data[0].email;  // autocomplete + checked

❌ instanceof על interface

        if (x instanceof Logger) { }
        // ❌ 'Logger' only refers to a type,
        //    but is being used as a value here.

✅ interface לא קיים בזמן ריצה

        if (x instanceof ConsoleLogger) { } // a class
        if ("info" in x) { }  // field check (part 3)
ושוב: שדה אופציונלי (?) – תמיד לבדוק או לתת ברירת מחדל עם ?? לפני שימוש.

Type Aliases – שמות לטיפוסים

literal types, tuple, intersection (&) ו-Utility Types · examples/02-type-aliases.ts

type – שם לכל טיפוס

  • type נותן שם לטיפוס – כל טיפוס: פרימיטיבי, אובייקט, פונקציה
  • timeout: Milliseconds אומר יותר מ-timeout: number
  • טיפוס פונקציה: מגדירים פעם אחת את החתימה, ו-TS מסיק את הפרמטרים
alias הוא רק שם נוסף: UserId ו-number הם אותו טיפוס – והבדיקה היא של number.
        type UserId = number;
        type Url = string;
        type Milliseconds = number;
        type Point = { x: number; y: number };             // אובייקט
        type Assertion = (actual: unknown, expected: unknown) => boolean;

        function fetchUser(id: UserId, base: Url, timeout: Milliseconds) {
          return `GET ${base}/users/${id} (timeout ${timeout}ms)`;
        }
        const click: Point = { x: 120, y: 340 };
        const strictEquals: Assertion = (a, e) => a === e;  // a, e: unknown

        console.log(fetchUser(7, "http://localhost:3000", 5000));
        console.log("Click at", click, strictEquals(1, "1"));

        const uid: UserId = "7";
        // ❌ Type 'string' is not assignable to type 'number'.
      
        GET http://localhost:3000/users/7 (timeout 5000ms)
        Click at { x: 120, y: 340 } false

Literal types – רק ערכים מסוימים מותרים

  • טיפוס יכול להיות ערך מדויק: "GET", 200, true
  • איחוד של literals עם | = רשימה סגורה של ערכים חוקיים
  • טעות כתיב נתפסת מיד – גם הבדל של אות גדולה/קטנה
  • VS Code משלים אוטומטית את האפשרויות
מתאים ל: שיטות HTTP, דפדפנים, סביבות, סטטוסים של טסט, רמות חומרה.
        type HttpMethod = "GET" | "POST" | "PUT" | "PATCH" | "DELETE";
        type Browser = "chromium" | "firefox" | "webkit";

        function request(method: HttpMethod, path: string): string {
          return `${method} ${path}`;
        }
        console.log(request("POST", "/users"));
        console.log(request("DELETE", "/users/7"));

        request("FETCH", "/users");     // טעות כתיב נתפסת מיד
        // ❌ Argument of type '"FETCH"' is not assignable
        //    to parameter of type 'HttpMethod'.
        request("get", "/users");
        // ❌ Argument of type '"get"' is not assignable
        //    to parameter of type 'HttpMethod'.
      
        POST /users
        DELETE /users/7

מלכודת נפוצה: let "מרחיב" ל-string

הצהרההטיפוס ש-TS מסיק
let m = "GET"string (אפשר לשנות לכל מחרוזת)
const m = "GET""GET" (לא ישתנה לעולם)
let m: HttpMethod = "GET"HttpMethod
  • let בלי טיפוס = "מחרוזת כלשהי" – ולכן לא מתאים ל-HttpMethod
  • הפתרון: const, או טיפוס מפורש
        let method = "GET";
        request(method, "/users");
        // ❌ Argument of type 'string' is not
        //    assignable to parameter of type 'HttpMethod'.

        const m2 = "GET";              // ✅ type is "GET"
        let m3: HttpMethod = "GET";    // ✅ explicit type
        m3 = "PUT";                    // ✅ still HttpMethod
        console.log(request(m2, "/a"), request(m3, "/b"));

        m3 = "OPTIONS";
        // ❌ Type '"OPTIONS"' is not assignable
        //    to type 'HttpMethod'.
      
        GET /a PUT /b

Union של literals + Record – מילון שלם

  • Record<Browser, number> = אובייקט עם בדיוק מפתח לכל דפדפן
  • שכחתם דפדפן? שגיאה. הוספתם מפתח שלא קיים? שגיאה
  • הוספתם "edge" ל-Browser? TS יראה לכם כל מקום שצריך לעדכן
        const timeouts: Record<Browser, number> = {
          chromium: 30_000,
          firefox: 45_000,
          webkit: 60_000,
        };
        function timeoutFor(browser: Browser): string {
          return `${browser}: ${timeouts[browser] / 1000}s`;
        }
        console.log(timeoutFor("webkit"));
        const all: Browser[] = ["chromium", "firefox", "webkit"];
        console.log(all.map(timeoutFor).join(" | "));

        const t1: Record<Browser, number> = {
          chromium: 30_000, firefox: 45_000 };
        // ❌ Property 'webkit' is missing in type
        //    '{ chromium: number; firefox: number; }'
        //    but required in type 'Record<Browser, number>'.
      
        webkit: 60s
        chromium: 30s | firefox: 45s | webkit: 60s

Tuple – מערך באורך וסדר קבועים

  • [code: number, text: string] – בדיוק 2 איברים, בסדר הזה
  • השמות (code, text) רק לתיעוד – מופיעים בהשלמה האוטומטית
  • נוח להחזרת כמה ערכים מפונקציה + פירוק (destructuring)
  • אורך שגוי או סדר הפוך – נתפסים
        type StatusLine = [code: number, text: string];
        const ok: StatusLine = [200, "OK"];
        const [code, text] = ok;
        console.log(`Status ${code} ${text}`);

        function minMax(durations: number[]): [min: number, max: number] {
          return [Math.min(...durations), Math.max(...durations)];
        }
        const [fastest, slowest] = minMax([820, 310, 1450, 640]);
        console.log(`fastest ${fastest}ms, slowest ${slowest}ms`);

        const a: StatusLine = [200];
        // ❌ Type '[number]' is not assignable to type 'StatusLine'.
        //    Source has 1 element(s) but target requires 2.
        const b: StatusLine = ["OK", 200];
        // ❌ Type 'string' is not assignable to type 'number'.
      
        Status 200 OK
        fastest 310ms, slowest 1450ms

Intersection (&) – שילוב טיפוסים

  • A & B = אובייקט שיש בו גם את כל השדות של A וגם של B
  • בונים טיפוסים מ"חלקים" קטנים לשימוש חוזר: WithTimestamps, WithAuth
  • זה ה"extends" של type
אל תתבלבלו: | = אחד מ-, & = כולם יחד.
        type WithTimestamps = { createdAt: string; updatedAt: string };
        type Bug = { id: number; title: string };
        type StoredBug = Bug & WithTimestamps;

        const stored: StoredBug = {
          id: 1, title: "Broken link",
