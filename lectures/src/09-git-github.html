Repository ו-Commit

שומרים "תמונות מצב" של קוד הבדיקות

מושגי יסוד ושלושת האזורים של Git

Repository (repo)

תיקיית פרויקט שגיט עוקב אחריה. ההיסטוריה בתיקייה הנסתרת .git.

Commit

"תמונת מצב" של הקבצים, עם מחבר, תאריך והודעה – נקודה שאפשר לחזור אליה.

Hash

מזהה ייחודי של commit, למשל 503e1a9 (קיצור של 40 תווים).

HEAD

"אתם נמצאים כאן" – ה-commit הנוכחי. HEAD~1 = זה שלפניו.

Working Directoryהקבצים שאתם עורכים

Staging Areagit add – מה ייכנס ל-commit הבא

למה צריך Staging? כדי לבחור מה נכנס ל-commit. שיניתם בדיקה וגם קובץ הגדרות? אפשר לשמור כל אחד ב-commit נפרד.

.gitignore – מה לא נכנס לגיט

  • תלויות – מותקנות מחדש עם npm install
  • דוחות – נוצרים בכל ריצה (וב-CI נשמרים כ-artifacts)
  • סיסמאות וטוקנים – אף פעם לא ב-commit
  • !.env.example – "חריג": קובץ דוגמה בלי ערכים אמיתיים כן נכנס
  • תבנית מלאה: templates/gitignore-node-ts.txt

        *.log

יוצרים .gitignore לפני ה-git add . הראשון – אחרת node_modules, .env ודוחות נכנסים ל-Staging.

הודעות commit טובות

  • שורה ראשונה קצרה (עד ~50 תווים), בלשון ציווי: Add login tests
  • commit אחד = שינוי לוגי אחד – לא לערבב תיקון באג + רפקטור + פיצ'ר
  • מתי? בכל פעם שהגעתם למצב יציב שעובד (הבדיקות עוברות)
  • אף פעם לא commit לסיסמאות, טוקנים או .env

הכללים המלאים: templates/commit-conventions.md

❌ לא כך

          git commit -m "fix"
          git commit -m "added some stuff"
          git commit -m "wip"

✅ כך (Conventional Commits)

          git commit -m "feat: add cart API tests"
          git commit -m "fix: wait for spinner before checkout"
          git commit -m "test: cover negative login scenarios"
          git commit -m "ci: run tests on pull requests"

חלק 2

Branches ו-Merge

עבודה במקביל בלי לשבור את main

Branch – קו פיתוח נפרד (מצביע ל-commit)

  • Branch = תווית שמצביעה על commit. commit חדש ← התווית זזה קדימה
  • HEAD = הענף הנוכחי · ענף חדש לא מעתיק קבצים – זול ומהיר
  • main – הקוד היציב; כל משימה בענף משלו: feature/..., fix/...
  • git branch – רשימה (* = הנוכחי)
  • git switch -c – יצירה + מעבר (בעבר: checkout -b)
  • במעבר ענף הקבצים מתחלפים: ב-main עוד אין checkout.spec.ts
        git branch
        git switch -c feature/checkout-tests
        # כאן: קובץ בדיקה חדש ושני commits
        git log --oneline --graph --all
        git switch main
        ls
      
        * main
        Switched to a new branch 'feature/checkout-tests'
        * 28870dd (HEAD -> feature/checkout-tests) Add coupon test
        * b11a5ec Add checkout tests
        * e7e1fbe (main) Initial commit
        Switched to branch 'main'
        README.md

Fast-forward merge – כש-main לא התקדם

לפני: main עדיין על ה-commit הראשון · אחרי: git פשוט "מקדם" את main קדימה – בלי commit חדש

Initial commit 
←
Add checkout tests 
←
Add coupon testmain + feature/checkout-tests
  • ממזגים לתוך הענף שעומדים עליו: קודם switch main
  • המילה Fast-forward בפלט = לא נוצר merge commit
  • היסטוריה בקו ישר
        git switch main
        git merge feature/checkout-tests
        git log --oneline --graph --all
      
        Updating e7e1fbe..28870dd
        Fast-forward
         checkout.spec.ts | 2 ++
         1 file changed, 2 insertions(+)
         create mode 100644 checkout.spec.ts

        * 28870dd (HEAD -> main, feature/checkout-tests) Add coupon test
        * b11a5ec Add checkout tests
        * e7e1fbe Initial commit

כשהענפים התפצלו – merge commit עם שני הורים

  • תיקנתם באג בענף, ובינתיים גם main התקדם – אי אפשר "לקדם"
  • Git מבצע מיזוג תלת-כיווני (3-way) ויוצר merge commit
  • שורות שונות שונו – המיזוג אוטומטי · %p = שני ההורים
  • --no-edit – בלי לפתוח עורך להודעה
git merge --no-ff יוצר merge commit תמיד – גם כשאפשר fast-forward. כך ממזג GitHub Pull Request.

        git switch main

        git merge --no-edit bugfix/flaky-search
        git log --oneline --graph --all
        git log -1 --format="%h %p %s"

ניקוי ענפים וטעויות נפוצות

  • ענף שמוזג – git branch -d: ה-commits נשארים ב-main
  • ענף שלא מוזג – -d מסרב: הגנה מאיבוד עבודה
  • --merged / --no-merged – מה כבר מוזג ל-HEAD
  • ענף קיים? בלי -c · עבדתם ישר על main? פתחו ענף ובקשו PR
  • שינוי לא שמור חוסם מעבר ענף ← commit, או git stash (חלק 5)
git branch -D (גדולה) מוחק בכוח – רק אם בטוחים.

Merge Conflicts

כששני ענפים שינו את אותה שורה

מתי יש קונפליקט – ומתי לא?

settings.ts – נקודת ההתחלה ב-main:

        export const settings = {
          baseUrl: "http://localhost:3000",
          browser: "chromium",
          retries: 0,
          workers: 4,
        };

שורות שונות ← מיזוג אוטומטי

ענף feature/firefox שינה browser, ו-main שינה workers

אותה שורה ← קונפליקט

ענף אחד: retries: 2, ו-main: retries: 1. Git לא יודע מי צודק.

        git merge --no-edit feature/firefox
      
        Auto-merging settings.ts
        Merge made by the 'ort' strategy.
         settings.ts | 2 +-
         1 file changed, 1 insertion(+), 1 deletion(-)
      
        cat settings.ts
      
        export const settings = {
          baseUrl: "http://localhost:3000",
          browser: "firefox",
          retries: 0,
          workers: 2,
        };

יוצרים קונפליקט – ואנטומיה שלו

        git switch -c feature/ci-retries
        git commit -am "Use 2 retries"   # retries: 0 → 2
        git switch main
        git commit -am "Use 1 retry"     # retries: 0 → 1
        git merge feature/ci-retries
      
        Auto-merging settings.ts
        CONFLICT (content): Merge conflict in settings.ts
        Automatic merge failed; fix conflicts and then commit the result.
  • -a = add אוטומטי לכל קובץ מוכר ששונה
  • המיזוג "באמצע": git status מציג both modified: settings.ts (בקצר: UU)
  • VS Code מציג כפתורים: Accept Current / Incoming / Both

cat settings.ts:

        export const settings = {
          baseUrl: "http://localhost:3000",
          browser: "firefox",
        <<<<<<< HEAD
          retries: 1,
        =======
          retries: 2,
        >>>>>>> feature/ci-retries
          workers: 2,
        };
  • <<<<<<< HEAD – הגרסה שלכם
  • ======= – מפריד
  • >>>>>>> branch – הגרסה שממזגים
  • מחוץ לסימונים – כבר מוזג

פתרון קונפליקט – צעד אחר צעד

←
2. מחליטיםשלנו / שלהם / שילוב
←
3. מוחקיםאת שורות הסימון
←
4. git add"נפתר"
←
5. git commitמשלים merge

שילוב של שני הצדדים: 2 ב-CI, 0 מקומית

        export const settings = {
          baseUrl: "http://localhost:3000",
          browser: "firefox",
          retries: process.env.CI ? 2 : 0,
          workers: 2,
        };

        git commit --no-edit

        git diff --cached --check
      
        settings.ts:4: leftover conflict marker
        settings.ts:6: leftover conflict marker
        settings.ts:8: leftover conflict marker
אחרי פתרון – הריצו את הבדיקות! קוד שמתקמפל אחרי merge עדיין יכול להיות שגוי.
מניעה: ענפים קצרי-חיים, PR קטנים, git pull ל-main לעתים קרובות.

בחירת צד שלם, או ביטול המיזוג

ours / theirs – לוקחים גרסה שלמה של צד אחד:

        git merge feature/new-users        # CONFLICT
        git checkout --theirs test-data/users.csv
        git add test-data/users.csv
        git commit --no-edit
        cat test-data/users.csv
      
        Updated 1 path from the index
        [main 25b57c6] Merge branch 'feature/new-users'
        username,password
        admin,NewPass2026
        viewer,View123

בזמן merge: ours = הענף שעומדים עליו (main) · theirs = הענף שממזגים

התחרטתם? חוזרים למצב שלפני ה-merge:

        git merge experiment/long-timeout  # CONFLICT
        git merge --abort
        git status
        git branch --no-merged
      
        On branch main
        nothing to commit, working tree clean
          experiment/long-timeout

שום דבר לא אבד: הענף עדיין קיים ואפשר למזג אותו מאוחר יותר.

restore ו-restore --staged

הוצאה מ-Staging – הקובץ נשאר בדיסק:

        git add .
        git status --short
        git restore --staged local-notes.txt
        git status --short
      
        A  local-notes.txt
        A  tests/cart.spec.ts

        A  tests/cart.spec.ts
        ?? local-notes.txt

הערות פרטיות לא נכנסו ל-commit, אבל לא נמחקו.

ביטול שינוי שלא נשמר – חזרה ל-commit האחרון:

        echo BROKEN >> tests/cart.spec.ts
        git status --short
        git restore tests/cart.spec.ts
        git status --short
        cat tests/cart.spec.ts
      
         M tests/cart.spec.ts

        test('add item to cart', () => {});
git restore <file> מוחק את השינוי לתמיד – אין "undo".

commit --amend – תיקון ה-commit האחרון

  • שגיאת כתיב בהודעה, או קובץ שנשכח
  • --amend מחליף את ה-commit האחרון בחדש (hash חדש!)
  • מה שב-Staging נכנס יחד איתו
רק לפני push. אחרי push, amend יוצר commit אחר – ההיסטוריה שלכם והשרת נפרדו (diverged) וה-push נדחה (non-fast-forward). push --force ידרוס עבודה של אחרים – משתמשים ב-revert או ב-commit תיקון חדש.

reset – הזזת הענף אחורה (שלושה מצבים)

פקודהה-commitהשינויים שלומתי
git reset --soft HEAD~1מבוטלנשארים ב-Staging"לאחד" או לכתוב מחדש commit
git reset HEAD~1 (mixed)מבוטלנשארים בקבצים, מחוץ ל-Stagingלסדר מחדש מה נכנס
git reset --hard HEAD~1מבוטלנמחקים ⚠️לזרוק ניסוי מקומי

git status --short
A  tests/a.spec.ts
git reset HEAD~1

git reset --hard HEAD~2

revert מול reset: revert מוסיף commit ומשאיר היסטוריה – בטוח אחרי push. reset כותב היסטוריה מחדש – רק לניסוי מקומי שלא נדחף (אחרת push --force, שחסום ל-main). לפני reset --hard הריצו git status.

reflog – רשת הביטחון

  • "זרקנו" שני commits של ניסוי:
    git reset --hard HEAD~2
  • git log כבר לא מציג אותם…
  • git reflog = יומן של כל מקום ש-HEAD היה בו (מקומי, ~90 יום)
  • מוצאים את ה-hash ויוצרים ממנו ענף – העבודה חזרה
reflog מציל רק מה שנכנס ל-commit. שינוי שלא נשמר ונמחק – אבד.
        git reset --hard HEAD~2
        git reflog -4

        03a7763 HEAD@{1}: commit: WIP experiment 2
        7079159 HEAD@{2}: commit: WIP experiment 1
        d557199 (HEAD -> main) HEAD@{3}: revert: Revert "Skip checkout test"

        git log --oneline -3 rescue/experiment
      
        03a7763 (rescue/experiment) WIP experiment 2
        7079159 WIP experiment 1
        d557199 (HEAD -> main) Revert "Skip checkout test"

stash – להחביא עבודה באמצע

התרחיש: באמצע בדיקה חדשה מגיע באג דחוף. מחביאים (stash push), מתקנים בענף נפרד, ומחזירים (stash pop).

  • תמיד עם -m "..." – כדי לזכור מה החבאתם
  • git stash רגיל לא לוקח קבצים חדשים (??) · -u – כולל untracked
  • stash list – הרשימה · stash show – מה בפנים
  • pop = מחזיר ומוחק · apply = מחזיר ומשאיר · drop = מחיקה

        # ...מתקנים בענף נפרד, חוזרים – ואז

        git stash list
        git stash show -u --stat stash@{0}

        stash@{0}: On main: WIP: slack reporter
