למה צריך פונקציות? (DRY)

❌ אותו חישוב שוב ושוב

        // בדיקה 1
        const rate1 = Math.round((45 / 50) * 100);
        // בדיקה 2
        const rate2 = Math.round((18 / 20) * 100);
        // בדיקה 3 – שכחנו לעגל...
        const rate3 = (7 / 9) * 100; // 77.777...

✅ פונקציה אחת עם שם ברור

        function rate(passed: number, total: number) {
          return Math.round((passed / total) * 100);
        }
        const rate1 = rate(45, 50); // 90
        const rate2 = rate(18, 20); // 90
        const rate3 = rate(7, 9);   // 78
  • פונקציה = קטע קוד עם שם, שאפשר לקרוא לו שוב ושוב עם נתונים שונים
  • DRY – Don't Repeat Yourself: מתקנים באג או משנים לוגיקה במקום אחד
  • שם טוב (calculatePassRate) מסביר מה קורה – בלי לקרוא את החישוב

אנטומיה של פונקציה: פרמטרים וערך חזרה

  • function – מילת המפתח
  • calculatePassRate – השם (פועל שמתאר מה היא עושה)
  • (passed: number, ...) – פרמטרים, לכל אחד טיפוס
  • : number אחרי הסוגריים – טיפוס החזרה
  • return – מחזיר ערך ומסיים את הפונקציה
        // function <name>(<param>: <type>, ...): <return type>
        function calculatePassRate(passed: number, total: number): number {
          if (total === 0) return 0; // לא מחלקים באפס
          return Math.round((passed / total) * 100);
        }

        console.log(calculatePassRate(45, 50));
        console.log(calculatePassRate(7, 9));
        console.log(calculatePassRate(0, 0));

      function summarize(
        results: boolean[],
      ): { passed: number; failed: number } {
        let passed = 0;
        for (const r of results) if (r) passed++;
        return { passed, failed: results.length - passed };
      }

      const summary = summarize([true, true, false, true]);
      console.log(summary);
      console.log(summary.failed);

      // destructuring
      const { passed, failed } = summarize([true, false]);
      console.log(passed, failed);

פונקציה כערך: function expression וטיפוס של פונקציה

  • Validator – טיפוס של פונקציה, "חוזה": מקבלת string ומחזירה boolean
  • check מריצה כל בדיקה שעומדת בחוזה
        true false
        not empty: PASS
        has @: FAIL
      
      const isSuccess = function (status: number): boolean {
        return status >= 200 && status < 300;
      };
      console.log(isSuccess(201), isSuccess(500));

      type Validator = (value: string) => boolean;
      const notEmpty: Validator = function (value) {
        return value.trim().length > 0;
      };
      const hasAt: Validator = function (value) {
        return value.includes("@");
      };

      function check(label: string, value: string, rule: Validator) {
        console.log(`${label}: ${rule(value) ? "PASS" : "FAIL"}`);
      }
      check("not empty", "noa@test.com", notEmpty);
      check("has @", "noa.test.com", hasAt);

Arrow Functions – תחביר

  • => ("חץ") מחליף את המילה function
  • שומרים אותה ב-const, כמו כל ערך
  • גוף עם { } → חייבים return
  • ביטוי יחיד בלי { } → מוחזר אוטומטית
  • כלל אצבע: callback קטן – arrow; פונקציית עזר עם שם – function
        4 6 8
        Hello QA false
      
      // פונקציה רגילה
      function double(n: number): number {
        return n * 2;
      }
      // אותה פונקציה בתחביר חץ
      const doubleArrow = (n: number): number => {
        return n * 2;
      };
      // גרסה מקוצרת: ביטוי יחיד מוחזר אוטומטית
      const doubleShort = (n: number) => n * 2;

      console.log(double(2), doubleArrow(3), doubleShort(4));

      const greet = (name: string) => `Hello ${name}`;
      const isOk = (code: number) => code === 200;
      console.log(greet("QA"), isOk(404));

טעויות נפוצות ב-Arrow Functions

❌ לא כך

        // סוגריים מסולסלים בלי החזרה
        const double = (n: number) => { n * 2 };
        console.log(double(5)); // undefined

        // אובייקט בלי סוגריים עגולים
        const toRow = (name: string) => { name: name };
        console.log(toRow("login")); // undefined

✅ כך

        // ביטוי יחיד, בלי סוגריים מסולסלים
        const double = (n: number) => n * 2;
        console.log(double(5)); // 10

        // אובייקט עטוף בסוגריים עגולים
        const toRow = (name: string) => ({ name: name });
        console.log(toRow("login")); // { name: 'login' }
למה? { מיד אחרי => נקרא תמיד כ"גוף פונקציה", לא כאובייקט. בלי return בגוף – מוחזר undefined

Callbacks – העברת פונקציה כפרמטר

  • Callback = פונקציה שמעבירים לפונקציה אחרת, והיא "קוראת לה בחזרה" כשצריך
  • () => void = "פונקציה בלי פרמטרים שלא מחזירה ערך"
  • runWithLog לא יודעת מה הפעולה – רק מתי להריץ אותה
runWithLog("x", clickLogin()) – קורא לפונקציה מיד ומעביר את התוצאה (void) → שגיאת קומפילציה

        runWithLog("login test", () => console.log("   ...clicking login"));

        const clickLogin = () => console.log("   click!");

map – המרה של כל איבר (במקום לולאת for)

  • for = "איך": יוצרים מערך ריק וממלאים ב-push
  • map = "מה": מריץ את ה-callback על כל איבר ומחזיר מערך חדש באותו אורך
  • מה שה-callback מחזיר = האיבר החדש; אפשר לקבל גם את האינדקס i
  • מחזירים אובייקט? עוטפים ב-({ ... })
  • for עדיין מתאים ללוגיקה מורכבת או ל-break
        // לולאת for – מערך ריק ו-push לכל איבר
        const loopNames: string[] = [];
        for (const r of results) loopNames.push(r.name);

        // map – אותה תוצאה בשורה אחת
        const names = results.map((r) => r.name);
        const numbered = results.map((r, i) => `${i + 1}.${r.name}`);
        const isError = [200, 404, 500].map((code) => code >= 400);
        const flags = results.map((r) => ({ slow: r.durationMs > 2000 }));

        console.log(names);
        console.log(numbered);
        console.log(isError);
        console.log(flags);

מחלקות, אובייקטים ובנאים

מה זה OOP ולמה זה חשוב באוטומציה?

  • מחלקה (class) – תבנית/שרטוט: אילו נתונים (שדות) ואילו פעולות (מתודות)
  • אובייקט (instance) – "עותק" חי שנוצר מהתבנית עם new
  • בנאי (constructor) – קוד שרץ פעם אחת ביצירת האובייקט ומאתחל אותו
  • באוטומציה: LoginPage, ApiClient, TestUser, Logger – כולם מחלקות
  • ארבעת העקרונות (בשיעורים הבאים): Encapsulation · Inheritance · Polymorphism · Abstraction

מחלקה: שדות ובנאי (constructor)

  • שם המחלקה ב-PascalCase: TestCase
  • שדות מוגדרים בראש המחלקה, עם טיפוס
  • constructor רץ אוטומטית ב-new, מקבל פרמטרים ומאתחל את השדות
  • this.id = id – "השדה של האובייקט הזה מקבל את הפרמטר"
  • שדות שלא מגיעים מבחוץ מקבלים ערך התחלתי קבוע
      class TestCase {
        // שדות (properties)
        id: string;
        title: string;
        steps: string[];
        status: "not-run" | "passed" | "failed";

        // בנאי – רץ פעם אחת, כשיוצרים אובייקט עם new
        constructor(id: string, title: string) {
          this.id = id; // this = האובייקט שנוצר עכשיו
          this.title = title;
          this.steps = [];
          this.status = "not-run";
        }

        // מתודות – בשקף הבא
      }

מתודות, ויצירת אובייקטים עם new

      class TestCase {
        // שדות ובנאי – מהשקף הקודם

        addStep(step: string): void {
          this.steps.push(step);
        }
        markPassed(): void {
          this.status = "passed";
        }
        markFailed(): void {
          this.status = "failed";
        }
        summary(): string {
          return `${this.id} | ${this.title} | ${this.status}`;
        }
      }
    
        const loginTest = new TestCase("TC-001", "Valid login");
        loginTest.addStep("Open /login");
        loginTest.addStep("Click Login");
        loginTest.markPassed();

        logoutTest.markFailed();

        console.log(logoutTest.summary());
        console.log(loginTest.steps);

מתודה = פונקציה בתוך המחלקה, ניגשת לשדות דרך this. ב-new: נוצר אובייקט, ה-constructor מאתחל אותו, והוא מוחזר – כל new = אובייקט עצמאי

אתחול שדה, private ו-getter

  • אתחול ישיר בשדה (= []) – בלי constructor
  • private – נגיש רק מתוך המחלקה (מגן על המצב מבחוץ)
  • get = "שדה מחושב": נכתב כמו מתודה, נקרא בלי סוגריים
  • נעמיק ב-private וב-getters בשיעור הבא
        Run pass rate: 75 %
      
      class TestRun {
        private results: boolean[] = [];

        record(passed: boolean): void {
          this.results.push(passed);
        }

        get passRate(): number {
          if (this.results.length === 0) return 0;
          const passed = this.results.filter((r) => r).length;
          return Math.round((passed / this.results.length) * 100);
        }
      }

      const run = new TestRun();
      [true, true, false, true].forEach((r) => run.record(r));
      console.log("Run pass rate:", run.passRate, "%");
      // run.results     ❌ Property 'results' is private
      // run.passRate()  ❌ not callable – it's a 'get' accessor

למה OOP באוטומציה? Page Object Model

Page Object = מחלקה שמייצגת עמוד באתר: השדות הם הכתובת והסלקטורים, המתודות הן הפעולות שמשתמש עושה בעמוד.

❌ בלי Page Object

  • הסלקטורים (#query, #search-btn) כתובים בתוך כל טסט
  • סלקטור השתנה → מתקנים עשרות טסטים
  • הטסט מלא בפרטים טכניים – קשה לראות מה בודקים

✅ עם Page Object

  • כל הסלקטורים של העמוד במחלקה אחת
  • סלקטור השתנה → מתקנים במקום אחד
  • הטסט קורא כמו תרחיש: searchPage.search("laptop")

      type Status = "passed" | "failed";
      type Result = { name: string; status: Status; ms: number };

      class Suite {
        private results: Result[] = [];
        constructor(public name: string) {}

        add(name: string, status: Status, ms = 0): void {
          this.results.push({ name, status, ms });
        }
        report(): string {
          const total = this.results.reduce((sum, r) => sum + r.ms, 0);
          const failed = this.results
            .filter((r) => r.status === "failed")
            .map((r) => r.name);
          const names = failed.join(", ") || "none";
          return `${this.name}: ${total}ms, failed: ${names}`;
        }
      }
