מה זה CI, ומה זה GitHub Actions?

push / PRמישהו משנה קוד
←
GitHub Actionsמזהה את האירוע וקורא את קובץ ה-YAML
←
Runnerמכונה נקייה מריצה את הבדיקות
←
תוצאה✅ / ❌ + דוחות להורדה
  • CI (Continuous Integration) – כל שינוי בקוד נבדק אוטומטית, מיד, על מכונה נקייה – לא "אצלי זה עובד"
  • GitHub Actions – שירות ה-CI המובנה ב-GitHub: קובץ YAML בתוך ה-repo מגדיר מה להריץ ומתי
  • Runner – מכונה וירטואלית זמנית (Ubuntu / Windows / macOS) שנוצרת לריצה ונמחקת בסופה
  • לבודקים: הבדיקות שכתבתם רצות לבד – על כל PR, כל לילה ובלחיצת כפתור – והדוחות נשמרים
ב-repo ציבורי הדקות חינמיות; ב-repo פרטי יש מכסת דקות חודשית – לכן חשוב שה-Pipeline יהיה מהיר וחכם

Pipeline מקומי

מה שרת CI עושה בפועל – ונריץ את אותם שלבים על המחשב שלנו

CI = חמש פעולות פשוטות

1. מריץפקודות לפי סדר שלבים
←
2. בודקexit code של כל פקודה
←
3. עוצרבכישלון הראשון (fail fast)
←
4. שומרתוצרים (artifacts)
←
5. מדווחירוק / אדום
  • exit code – המספר שכל תוכנית מחזירה כשהיא מסתיימת
  • 0 = הצלחה · כל מספר אחר = כישלון
  • $? ב-bash מחזיק את ה-exit code של הפקודה האחרונה
  • כך GitHub Actions מחליט אם step עבר: כל קוד שאינו 0 ← ❌
        node -e "console.log('ok')"
        echo $?      # 0 = success
        node -e "process.exit(1)"
        echo $?      # 1 = failure
      
        ok
        0
        1

examples/01-local-pipeline.ts – הקוד

    interface Stage {
      name: string;
      command: string[];
      continueOnError?: boolean;   // כמו continue-on-error ב-YAML
    }

    const stages: Stage[] = [
      { name: "Typecheck", command: [process.execPath, "node_modules/typescript/bin/tsc", "--noEmit"] },
      { name: "Solutions (smoke run)", command: [...tsx, "scripts/run-all-examples.ts", "solutions"] },
      { name: "API tests + reports", command: [...tsx, "lessons/10-ci-cd-logs-reports/examples/04-mini-runner-with-reports.ts"] },
    ];

    for (const stage of stages) {
      const r = spawnSync(stage.command[0], stage.command.slice(1), { encoding: "utf8" });
      const ok = r.status === 0;                       // status = exit code
      results.push({ name: stage.name, ok, seconds });
      if (!ok && !stage.continueOnError) {
        console.log("\n⛔ Fail fast: the next stages will not run");
        break;
      }
    }

Hello Actions

triggers · run / uses · env · ביטויים ${{ }} · outputs

Workflow ראשון ב-GitHub Actions

  • הקובץ חייב להיות ב-.github/workflows/ · on – מתי רץ · jobs ← steps
  • run – פקודת shell, כמו בטרמינל; | = כמה שורות
  • uses: owner/repo@version – Action מוכנה מה-Marketplace, פרמטרים ב-with
  • ה-runner מתחיל ריק: ls -la לפני actions/checkout מראה תיקייה ריקה – אין קוד!
  • גם node_modules לא קיים – כל job מריץ npm ci מחדש
  • התוצאה: לשונית Actions ב-GitHub
      # .github/workflows/hello.yml
      name: Hello Actions

      on:
        push:                    # בכל push לכל ענף
        workflow_dispatch:       # כפתור "Run workflow"

      jobs:
        hello:
          runs-on: ubuntu-latest   # מכונה נקייה שגיטהאב מספק
          steps:
            - name: Say hello
              run: echo "Hello from GitHub Actions 👋"

            - name: Who and what triggered me?
              run: |
                echo "Event:  ${{ github.event_name }}"
                echo "Branch: ${{ github.ref_name }}"

            - name: Checkout the code
              uses: actions/checkout@v6   # פעולה מוכנה
            - run: ls -la

  • env ב-3 רמות: workflow → job → step; הקרוב גובר

  • $NAME – משתנה סביבה שה-shell קורא בזמן ריצה

        APP_NAME: qa-course            # כל ה-jobs
      jobs:
        greet:
          runs-on: ubuntu-latest

            BASE_URL: https://qa.example.com   # ה-job הזה

                GREETING: Hi                   # ה-step הזה

Contexts – המידע הזמין בתוך ${{ }}: github · env · vars · secrets · inputs · matrix · steps · needs · job · runner

העברת מידע: $GITHUB_OUTPUT, $GITHUB_ENV, $GITHUB_STEP_SUMMARY

  • $GITHUB_OUTPUT ← key=value ← נקרא דרך steps.<id>.outputs
  • $GITHUB_ENV ← KEY=value ← משתנה סביבה ל-steps הבאים
  • $GITHUB_STEP_SUMMARY ← Markdown ← מוצג בעמוד הריצה
המסלול של output: step עם id ← outputs של ה-job ← job אחר דרך needs
❌ export SUITE=smoke לא שורד ל-step הבא – כותבים ל-$GITHUB_ENV
❌ output בלי id או בלי outputs ברמת ה-job ← needs.greet.outputs.branch ריק
      greet:
        runs-on: ubuntu-latest
        outputs:
          branch: ${{ steps.info.outputs.branch }}
        steps:
          - id: info
            run: echo "branch=${{ github.ref_name }}" >> "$GITHUB_OUTPUT"
          - run: echo "SUITE=smoke" >> "$GITHUB_ENV"
          - run: echo "Suite is $SUITE"       # smoke
          - run: echo "### ✅ Greeted" >> "$GITHUB_STEP_SUMMARY"
      report:
        needs: greet
        runs-on: ubuntu-latest
        steps:
          - run: echo "greet ran on ${{ needs.greet.outputs.branch }}"

jobs במקביל מול needs – ה-Pipeline של הקורס

  • ברירת מחדל: כל ה-jobs רצים במקביל, כל אחד על מכונה נפרדת
  • needs – "חכה ל-X ורוץ רק אם הצליח"; X נכשל ← התלויים בו skipped
  • ב-ci.yml של הקורס: tests ו-playwright תלויים שניהם ב-quality ← רצים במקביל זה לזה
  • קבצים לא עוברים בין jobs – רק outputs ו-artifacts
needs.X.resultמתי
successעבר
failureנכשל
cancelledבוטל

Matrix ו-Cache – אותו job על כמה גרסאות, בהתקנה מהירה

  • strategy.matrix – כל שילוב = job נפרד: 2 מערכות × 2 גרסאות = 4 jobs במקביל
  • הערך הנוכחי: ${{ matrix.os }} · ב-GitHub: test (ubuntu-latest, 22)
  • cache: npm – שומר את מטמון ההורדות של npm בין ריצות; המפתח = hash של package-lock.json
  • דורש package-lock.json ב-git (או cache-dependency-path) – אחרת שגיאה
npm cinpm install

      name: Tests
      on:
        pull_request:
          branches: [main]
      jobs:
        test:
          runs-on: ${{ matrix.os }}
          strategy:
            fail-fast: false
            matrix:
              os: [ubuntu-latest, windows-latest]
              node: [22, 24]

            - uses: actions/setup-node@v6
              with:
                node-version: ${{ matrix.node }}
                cache: npm
                cache-dependency-path: package-lock.json
            - run: npm ci
            - run: npm run solutions

Matrix מתקדם: exclude, include, fail-fast, max-parallel

  • exclude – מוריד שילוב (חוסך דקות)
  • include – מוסיף שילוב (או משתנה לשילוב קיים)
  • fail-fast (ברירת מחדל true) – כישלון אחד מבטל את השאר; false = רואים את כל התמונה
  • max-parallel: 2 – לכל היותר 2 מכונות בו-זמנית
  • continue-on-error – Node 25 ניסיוני לא יצבע את הריצה באדום
      test:
        runs-on: ${{ matrix.os }}
        continue-on-error: ${{ matrix.experimental == true }}
        strategy:
          fail-fast: false
          max-parallel: 2
          matrix:
            os: [ubuntu-latest, windows-latest]
            node: [22, 24]
            exclude:
              - os: windows-latest
                node: 22
            include:
              - os: ubuntu-latest
                node: 25
                experimental: true
      # => ubuntu/22, ubuntu/24, windows/24
      #    + ubuntu/25 (experimental) – 2 at a time

Artifacts – לשמור את הדוחות

  • המכונה נמחקת בסוף ← מה שלא הועלה – אבד
  • name – ייחודי בכל ריצה (במטריצה: כוללים matrix.node, אחרת התנגשות)
  • path – תיקייה, קובץ, או כמה שורות עם |
  • retention-days – כמה ימים לשמור (ברירת מחדל 90)
  • הורדה: עמוד הריצה ← Summary ← Artifacts (קובץ zip)

schedule (cron) · הפעלה ידנית עם inputs · concurrency

תחביר cron – 5 שדות, בזמן UTC

cronמשמעות
"0 0 * * 0-4"חצות UTC, ראשון–חמישי (02:00/03:00 בישראל)
"30 1 * * *"כל יום ב-01:30 UTC
"0 2 * * 1-5"02:00, שני–שישי
"0 6 * * 6"06:00 בשבת
"*/15 * * * *"כל 15 דקות (מינימום: 5)
      ┌──────── minute (0-59)
      │ ┌────── hour (0-23, UTC!)
      │ │ ┌──── day of month (1-31)
      │ │ │ ┌── month (1-12)
      │ │ │ │ ┌ day of week (0=Sun)
      │ │ │ │ │
      0 0 * * 0-4
  • * = כל ערך · 1-5 = טווח · */15 = כל 15 · 1,3 = רשימה
  • schedule רץ רק מהענף הראשי (default branch), ועלול להתעכב בשעות עומס
  • ב-repo ציבורי בלי פעילות 60 יום – GitHub משבית את ה-schedule

רגרסיה לילית + הפעלה ידנית עם פרמטרים

  • schedule – לפי cron, בזמן UTC
  • workflow_dispatch – Actions ← בוחרים Workflow ← Run workflow ← טופס עם השדות
  • קוראים את הערך: ${{ inputs.browser }} · בריצה מ-schedule השדות ריקים ← תמיד ברירת מחדל עם ||
  • --grep @regression – הרצה לפי תגיות
  • קובץ: examples/workflows/04-nightly-regression.yml
typeבטופס
string · numberשדה טקסט / מספר
choiceרשימה נפתחת (options)
booleanתיבת סימון
environmentבחירת Environment
      on:
        schedule:
          - cron: "0 0 * * 0-4"      # UTC
        workflow_dispatch:
          inputs:
            browser:
              type: choice
              options: [chromium, firefox, webkit]
              default: chromium
            debug:
              type: boolean
              default: false
      jobs:
        regression:
          runs-on: ubuntu-latest
          steps:       # ... checkout, setup-node, npm ci
            - run: |
                npx playwright install --with-deps \
                  ${{ inputs.browser || 'chromium' }}
            - if: ${{ inputs.debug }}
              run: echo "DEBUG=pw:api" >> "$GITHUB_ENV"
            - run: |
                npx playwright test --grep @regression \
                  --project=${{ inputs.browser || 'chromium' }}

  • false – הריצה החדשה ממתינה בתור

חלק 7

Quality Gate ל-Pull Request

אי אפשר למזג קוד שבור · קריאת לוגים · נעילת גרסאות

שער איכות לפני מיזוג: 05-pr-quality-gate.yml

  • בדיקות מהירות ראשונות – אם הקוד לא מתקמפל, לא מבזבזים דקות על UI
  • api-tests ו-ui-tests רצים במקביל – אחרי ה-typecheck
  • --shard=1/3 – Playwright מריץ רק שליש מהבדיקות
  • matrix של shard ← 3 מכונות, כל אחת שליש
  • artifact לכל shard עם שם ייחודי
  • with: { ... } – אותו YAML בכתיב מקוצר
      jobs:                # on: pull_request → branches: [main]
        lint-and-types:
          runs-on: ubuntu-latest
          steps:
            - uses: actions/checkout@v6
            - uses: actions/setup-node@v6
              with: { node-version: 22, cache: npm }
            - run: npm ci
            - run: npm run typecheck
        ui-tests:
          needs: lint-and-types
          runs-on: ubuntu-latest
          strategy:
            matrix:
              shard: [1, 2, 3]
          steps:
            # ... checkout, setup-node, npm ci, playwright install
            - run: npx playwright test tests/ui --shard=${{ matrix.shard }}/3
            - uses: actions/upload-artifact@v7
              if: always()
              with:
                name: ui-results-shard-${{ matrix.shard }}
                path: test-results/

להדק את ה-trigger: types, paths, draft, timeout

  • branches ב-pull_request = ענף היעד של ה-PR (ב-push: הענף שנדחף)
  • types – אילו פעולות על ה-PR (ברירת מחדל: opened, synchronize, reopened)
  • paths – רק אם השתנה קובץ תואם: PR שמשנה רק README לא מפעיל בדיקות
  • paths-ignore – ההפך; לא שניהם יחד באותו אירוע
  • PR בטיוטה (draft) – לא מבזבזים דקות
  • permissions מינימליות + כתיבה ל-PR · timeout-minutes לכל job
      name: PR Gate
      on:
        pull_request:
          branches: [main]
          types: [opened, synchronize, reopened]
          paths:
            - "lessons/**"
            - package-lock.json
      permissions:
        contents: read
        pull-requests: write
      jobs:
        lint:
          if: github.event.pull_request.draft == false
          runs-on: ubuntu-latest
          timeout-minutes: 10
          steps: [ ... ]
        tests:
          needs: lint
          runs-on: ubuntu-latest
          timeout-minutes: 15
          steps: [ ... ]

ה-job שמחליט: quality-gate

  • needs: [lint, tests] – מחכה לשניהם
  • if: always() – חייב לרוץ גם כשמשהו נכשל; בלי זה הוא skipped – ו-skipped עלול להיחשב כ"עבר"!
  • needs.*.result – רשימת התוצאות של כל ה-needs
  • exit 1 ← ה-gate אדום ← המיזוג חסום
  • Branch protection (Settings ← Rulesets): quality-gate = ה-check החובה היחיד
      quality-gate:
        needs: [lint, tests]
        if: always()
        runs-on: ubuntu-latest
        steps:
          - name: Write summary
            run: |
              echo "### Quality gate" >> "$GITHUB_STEP_SUMMARY"
              echo "- lint: ${{ needs.lint.result }}" >> "$GITHUB_STEP_SUMMARY"
              echo "- tests: ${{ needs.tests.result }}" >> "$GITHUB_STEP_SUMMARY"

          - name: Fail if a required job failed
            if: ${{ contains(needs.*.result, 'failure') || contains(needs.*.result, 'cancelled') }}
            run: |
              echo "A required job failed or was cancelled"
              exit 1

קריאת ריצה שנכשלה – סדר עבודה

  1. לשונית Actions ← הריצה האדומה ← איזה job ואיזה step נכשל?
  2. בלוג: השורה הראשונה עם Error – לא האחרונה (exit code 1 הוא רק התוצאה). Expected מול Received = לב הבעיה
  3. Summary ← artifacts ← playwright-report / allure-report ← Trace, screenshot, video
  4. השוואה לריצה קודמת שעברה: מה השתנה? (commit, סביבה, נתונים)
  5. החלטה: באג במוצר ← Bug report עם הראיות · באג בבדיקה ← תיקון + PR · סביבה ← DevOps
  6. Flaky? עבר ב-retry ← מסומן ב-Allure כ-flaky ← לטפל, לא להתעלם
Re-run failed jobs – מריץ שוב רק את מה שנכשל; עם "Enable debug logging" ← לוג מפורט · Trace מקומית: npx playwright show-trace trace.zip
