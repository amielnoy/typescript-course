Abstract Classes – מחלקות מופשטות

חוזה + קוד משותף · examples/01-abstract-classes.ts

הבעיה: ברירת מחדל מסוכנת

  • במחלקת בסיס רגילה חייבים לכתוב גוף לכל מתודה – גם כשאין מימוש הגיוני
  • אז כותבים "ברירת מחדל" כמו return true
  • מחלקה בת ששכחה לדרוס – מקבלת אותה בשקט
  • ובדיקות? עוברות, למרות שאף אחד לא בדק שהעמוד נטען 😱
באוטומציה זה הכי מסוכן: False Positive – בדיקה ירוקה שלא בודקת כלום.
        class UnsafeBasePage {
          isLoaded(): boolean {
            return true; // ברירת מחדל "זמנית"...
          }
        }
        // שכחנו לממש isLoaded – ואין שום אזהרה
        class CartPage extends UnsafeBasePage {}

        console.log("cart loaded?", new CartPage().isLoaded());
      
        cart loaded? true
ועוד בעיה: אפשר ליצור "עמוד כללי" חסר משמעות – new UnsafeBasePage().

מחלקה מופשטת

  • אי אפשר ליצור ממנה אובייקט ישירות: new BasePage() ❌
  • יכולה להכיל קוד משותף – מתודות ושדות רגילים
  • מגדירה מתודות abstract – בלי מימוש. כל בת חייבת לממש אותן
  • הקומפיילר מוודא שלא שכחתם לממש – "חוזה" שנאכף
  • השימוש הקלאסי באוטומציה: BasePage ב-Page Object Model, BaseTest, BaseApiClient

התחביר: abstract class ו-abstract method

  • abstract class – לפני המילה class
  • abstract baseUrl(): string; – חתימה בלבד, בלי גוף, מסתיימת ב-;
  • abstract readonly name – גם שדה יכול להיות abstract
  • describe() – קוד משותף שמשתמש בחלקים המופשטים
  • במימוש של חבר abstract בבת לא חובה לכתוב override (מותר)
        abstract class Environment {
          abstract readonly name: string;
          abstract baseUrl(): string;

          describe(): string {
            return `${this.name} -> ${this.baseUrl()}`;
          }
        }
        class DevEnv extends Environment {
          readonly name = "dev";
          baseUrl(): string { return "http://localhost:3000"; }
        }
        class StagingEnv extends Environment {
          readonly name = "staging";
          baseUrl(): string { return "https://staging.shop.test"; }
        }
        const envs: Environment[] = [new DevEnv(), new StagingEnv()];
        for (const env of envs) console.log(env.describe());
      
        dev -> http://localhost:3000
        staging -> https://staging.shop.test

הקומפיילר אוכף את החוזה

❌ ליצור מופע מהמחלקה המופשטת

        abstract class BasePage {
          constructor(protected baseUrl: string) {}
          abstract readonly path: string;
          abstract isLoaded(): boolean;
        }

        const p = new BasePage("x");
        // error TS2511: Cannot create an instance
        // of an abstract class.

הגיוני: ל-BasePage אין path ואין isLoaded – זה שלד חלקי.

❌ מחלקה בת ששכחה לממש

        class CartPage extends BasePage {
          readonly path = "/cart";
          // שכחנו את isLoaded...
        }
        // error TS2515: Non-abstract class
        // 'CartPage' does not implement inherited
        // abstract member isLoaded from class
        // 'BasePage'.

זה בדיוק ה-False Positive מהשקף הקודם – עכשיו נתפס לפני שהבדיקה רצה.

BasePage – הבסיס ל-Page Object Model

  • open() נכתב פעם אחת
  • כל עמוד מספק רק את מה שייחודי לו: path ו-isLoaded
  • שכחתם isLoaded? שגיאת קומפילציה
  • this.constructor.name – שם המחלקה האמיתית (LoginPage...) להודעות ברורות
  • נחזור לזה בשיעורי Playwright ו-POM
      abstract class BasePage {
        constructor(protected baseUrl: string) {}

        // כל עמוד חייב להגדיר נתיב ואיך מוודאים שנטען
        abstract readonly path: string;
        abstract isLoaded(): boolean;

        // קוד משותף לכל העמודים
        open(): void {
          console.log(`Navigating to ${this.baseUrl}${this.path}`);
          if (!this.isLoaded()) {
            throw new Error(`${this.constructor.name} did not load`);
          }
          console.log(`  ✔ ${this.constructor.name} loaded`);
        }
      }

העמודים עצמם: LoginPage, DashboardPage, BrokenPage

protected abstract – "חורים" שרק הבסיס ממלא

  • fillFields ו-button הם פרטי מימוש – הבדיקה לא אמורה לקרוא להם ישירות
  • protected abstract: הבת חייבת לממש, ורק המחלקה והבנות יכולות לקרוא
  • מבחוץ יש רק כניסה אחת: submit() – שמבטיחה סדר קבוע
        new SignupForm().fillFields();

        abstract class BaseForm {
          protected abstract fillFields(): void;
          protected abstract button(): string;

            console.log(`  click ${this.button()}`);
          }

קוד משותף בבסיס: BaseApiClient

  • בניית URL והוספת טוקן – פעם אחת ב-request
  • כל client מגדיר רק את resource ואת הפעולות שלו
  • baseUrl ו-token הם private – אפילו הבנות לא נוגעות בהם
  • תיקון באימות (למשל פורמט header חדש) = שינוי במקום אחד
        abstract class BaseApiClient {
          constructor(private baseUrl: string, private token: string) {}
          protected abstract readonly resource: string;

          protected request(method: string, id?: number): string {
            const path = id === undefined ? "" : `/${id}`;
            const url = `${this.baseUrl}/${this.resource}${path}`;
            const auth = `Bearer ${this.token.slice(0, 3)}...`;
            return `${method} ${url} (auth: ${auth})`;
          }
        }
        class UsersClient extends BaseApiClient {
          protected readonly resource = "users";
          getAll(): string { return this.request("GET"); }
          remove(id: number): string { return this.request("DELETE", id); }
        }
        const users = new UsersClient("http://localhost:3000", "abc123");
        console.log(users.remove(7));
      
        DELETE http://localhost:3000/users/7 (auth: Bearer abc...)

שלב 1: המחלקה המופשטת Check – Template Method

  • Outcome – מה כל בדיקה מחזירה
  • verify – "האם עבר?" (כל בדיקה אחרת)
  • describeFailure – הודעה ברורה כשנכשל
  • שתיהן protected abstract – רק run קורא להן
  • Template Method: run באב מגדירה את סדר הצעדים וקוראת ל"חורים" שהבנות ממלאות
  • הבנות לא יכולות "לשכוח" את ה-try/catch או לבנות Outcome לא נכון
      type Outcome = { name: string; passed: boolean; details: string };

      abstract class Check {
        constructor(public readonly name: string) {}

        protected abstract verify(): boolean;
        protected abstract describeFailure(): string;

        // הזרימה הקבועה – זהה לכל סוגי הבדיקות
        run(): Outcome {
          try {
            const passed = this.verify();
            const details = passed ? "ok" : this.describeFailure();
            return { name: this.name, passed, details };
          } catch (err) {
            const details = `error: ${(err as Error).message}`;
            return { name: this.name, passed: false, details };
          }
        }
      }

שלב 2: בדיקות קונקרטיות – EqualsCheck ו-ContainsCheck

      // <T> = טיפוס גנרי (שיעור 7) – כל סוג ערך
      class EqualsCheck<T> extends Check {
        constructor(name: string,
                    private actual: T,
                    private expected: T) {
          super(name);
        }
        protected verify(): boolean {
          return this.actual === this.expected;
        }
        protected describeFailure(): string {
          return `expected ${String(this.expected)}` +
            ` but got ${String(this.actual)}`;
        }
      }
    
      class ContainsCheck extends Check {
        constructor(name: string,
                    private text: string,
                    private fragment: string) {
          super(name);
        }
        protected verify(): boolean {
          return this.text.includes(this.fragment);
        }
        protected describeFailure(): string {
          return `"${this.text}" does not contain` +
            ` "${this.fragment}"`;
        }
      }
שימו לב כמה מעט קוד יש בכל בדיקה: רק "מה לבדוק" ו"מה להגיד כשנכשל". כל השאר – ב-run של Check.

שלב 3: ResponseTimeCheck – וגם מה קורה כשזורקים שגיאה

        class ResponseTimeCheck extends Check {
          constructor(name: string,
                      private ms: number,
                      private maxMs: number) {
            super(name);
          }
          protected verify(): boolean {
            if (this.ms < 0) {
              throw new Error("negative duration");
            }
            return this.ms <= this.maxMs;
          }
          protected describeFailure(): string {
            return `${this.ms}ms > limit ${this.maxMs}ms`;
          }
        }
verify זורקת שגיאה על נתון לא תקין – וה-catch ב-run הופך אותה לתוצאה נכשלת.

BaseTest: setup → execute → teardown

  • כל בדיקה אמיתית: הכנה, ביצוע, ניקוי
  • setup / teardown – מתודות רגילות "ריקות": בת דורסת רק אם צריך (עם override)
  • execute – abstract: בלי זה אין בדיקה
  • finally – רץ תמיד: גם אחרי הצלחה, גם אחרי שגיאה
teardown שלא רץ = דפדפן פתוח, משתמש מחובר, נתונים "מלוכלכים" לבדיקה הבאה.
      abstract class BaseTest {
        constructor(public readonly name: string) {}

        protected setup(): void {}           // אופציונלי
        protected abstract execute(): void;  // חובה
        protected teardown(): void {}        // אופציונלי

        run(): boolean {
          console.log(`▶ ${this.name}`);
          try {
            this.setup();
            this.execute();
            console.log("  ✔ passed");
            return true;
          } catch (err) {
            console.log(`  ✘ failed: ${(err as Error).message}`);
            return false;
          } finally {
            this.teardown(); // תמיד!
          }
        }
      }

בדיקה אמיתית: LoginTest

      // "הדפדפן" – מדומה, כדי שנוכל להריץ בלי Playwright
      class FakeBrowser {
        page = "about:blank";
        user: string | null = null;
        goto(path: string): void {
          this.page = path;
          console.log(`  goto ${path}`);
        }
        login(user: string, pass: string): void {
          if (pass === "secret") this.user = user;
        }
        close(): void {
          console.log("  browser closed");
        }
      }
    
      class LoginTest extends BaseTest {
        private browser = new FakeBrowser();
        constructor(private user: string,
                    private pass: string) {
          super(`login as ${user}`);
        }
        protected override setup(): void {
          this.browser.goto("/login");
        }
        protected execute(): void {
          this.browser.login(this.user, this.pass);
          if (this.browser.user !== this.user) {
            throw new Error(`"${this.user}" is not logged in`);
          }
        }
        protected override teardown(): void {
          this.browser.close();
        }
      }
setup/teardown דורסים מתודה רגילה ← override. execute מממש abstract ← בלי חובה.

מעקב: LoginTest("noa", "wrong").run()

  1. run של BaseTest מדפיסה ▶ login as noa
  2. this.setup() ← של LoginTest ← goto /login
  3. this.execute() ← הסיסמה שגויה ← browser.user נשאר null
  4. null !== "noa" ← throw
  5. קופצים ל-catch ← ✘ failed: ... ← return false
  6. לפני שהערך חוזר – finally ← teardown() ← browser closed
שימו לב: ✔ passed מודפס לפני browser closed – כי finally רץ אחרי ה-return, רגע לפני שהפונקציה באמת יוצאת.

Reporters – אותן תוצאות, פורמטים שונים

      abstract class Reporter {
        abstract render(results: Outcome[]): string;

        print(results: Outcome[]): void {
          console.log(`--- ${this.constructor.name} ---`);
          console.log(this.render(results));
        }
      }
      class DotsReporter extends Reporter {
        render(results: Outcome[]): string {
          return results
            .map((r) => (r.passed ? "." : "F"))
            .join("");
        }
      }
      class JsonReporter extends Reporter {
        render(results: Outcome[]): string {
          const failed =
            results.filter((r) => !r.passed).length;
          const total = results.length;
          return JSON.stringify({ total, failed });
        }
      }
    
        // outcomes – 5 התוצאות מ"שלב 4"
        const reporters: Reporter[] =
          [new DotsReporter(), new JsonReporter()];
        reporters.forEach((r) => r.print(outcomes));
      
        --- DotsReporter ---
        .F.FF
        --- JsonReporter ---
        {"total":5,"failed":3}
ב-CI נרצה JUnit XML, בטרמינל – נקודות, בדוח – HTML. הבדיקות לא משתנות, רק ה-Reporter.

טעויות נפוצות – במיני-פריימוורק

❌ teardown בתוך ה-try

        run(): void {
          try {
            this.execute();
            this.teardown(); // לא ירוץ אם execute זרקה!
          } catch (err) {
            console.log(`  ✘ ${(err as Error).message}`);
          }
        }
      
          ✘ element not found

אין "teardown" בפלט – הדפדפן נשאר פתוח.

✅ teardown ב-finally

        run(): void {
          try {
            this.execute();
          } catch (err) {
            console.log(`  ✘ ${(err as Error).message}`);
          } finally {
            this.teardown(); // תמיד רץ
          }
        }
  • גם לא לתפוס שגיאות בתוך verify של הבת – תנו ל-run לטפל
  • ולא להפוך את verify ל-public – הבדיקה רצה רק דרך run
