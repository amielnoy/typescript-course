הפתרון: פרמטר טיפוס <T>

פונקציה אחת · כל טיפוס · בטיחות מלאה – בדרך כלל TS מסיק את T לבד:

      function first<T>(items: T[]): T | undefined {
        return items[0];
      }

      const n = first([10, 20, 30]);    // number | undefined
      const s = first(["chromium"]);    // string | undefined

הסקת טיפוסים (Type Inference)

  • TS מסתכל על הארגומנטים ומסיק את T
  • מערך מעורב → T הוא union
  • מערך ריק → אין ממה להסיק (never)
  • ציון מפורש first<string> – כשאין ממה להסיק, או כדי ש-TS יבדוק אותנו
ברוב המקרים – לא כותבים את T. נותנים ל-TS להסיק.
      first([10, 20, 30]);       // T = number
      first(["login", "cart"]);  // T = string
      first([1, "two"]);         // T = string | number
      first([]);                 // T = never → returns undefined
      first<string>([]);         // explicit: T = string

      const n = first([10, 20, 30]);
      n?.toUpperCase();
      // ❌ Property 'toUpperCase' does not exist on type 'number'.

      first<string>([1, 2]);
      // ❌ Type 'number' is not assignable to type 'string'.

        function mapValues<T, R>(items: T[], fn: (item: T) => R): R[] {
          const out: R[] = [];

          return out;

readonly, as const ו-arrow function גנרית

  • readonly T[] – הפונקציה מבטיחה לא לשנות את המערך, ולכן מקבלת גם מערכים קבועים
  • as const – שומר את הערכים המדויקים: T = "chromium" | "firefox" | "webkit"
  • בלי as const – T היה סתם string
  • arrow function: ה-<T> נכתב לפני הסוגריים

      function randomItem<T>(items: readonly T[]): T {
        return items[Math.floor(Math.random() * items.length)];
      }

      const ALL = ["chromium", "firefox", "webkit"] as const;

      b2 = "edge";

דוגמה מעולם הבדיקות: retry<T>

  • בדיקות "מהבהבות" (flaky) – מנסים שוב כמה פעמים
  • retry לא יודעת מה הפעולה מחזירה – וגם לא צריכה
  • מה שה-action מחזיר – זה מה ש-retry מחזירה: כאן T = number
  • עובד גם ל-string, ל-User, לכל דבר
        attempt 1 failed: 503 Service Unavailable
        attempt 2 failed: 503 Service Unavailable
        status: 200 after 3 calls
      
      function retry<T>(action: () => T, attempts: number): T {
        let lastError: unknown;
        for (let i = 1; i <= attempts; i++) {
          try {
            return action();
          } catch (err) {
            lastError = err;
            console.log(`attempt ${i} failed: ${(err as Error).message}`);
          }
        }
        throw lastError;
      }

      let calls = 0;
      const status = retry(() => {
        calls++;
        if (calls < 3) throw new Error("503 Service Unavailable");
        return 200;
      }, 5); // status: number
      console.log("status:", status, "after", calls, "calls");

Result<T, E> – הצלחה או כישלון, עם טיפוסים

  • union גנרי: או value מסוג T, או error מסוג E
  • E = string – ברירת מחדל לשגיאה
  • אחרי if (r.ok) – TS יודע באיזה צד אנחנו (narrowing)
  • מחזירים כישלון כערך – בלי לזרוק שגיאה
        value: 201
        error: invalid status: abc
      
      type Result<T, E = string> =
        | { ok: true; value: T }
        | { ok: false; error: E };

      function parseStatus(raw: string): Result<number> {
        const code = Number(raw);
        if (Number.isInteger(code) && code >= 100 && code <= 599) {
          return { ok: true, value: code };
        }
        return { ok: false, error: `invalid status: ${raw}` };
      }

      for (const raw of ["200", "abc"]) {
        const r = parseStatus(raw);
        if (r.ok) console.log("value:", r.value + 1); // number
        else console.log("error:", r.error);          // string
      }
      parseStatus("1").value;
      // ❌ Property 'value' does not exist on type 'Result<number, string>'.

Constraints – למה צריך להגביל את T?

בתוך פונקציה גנרית, T יכול להיות כל דבר – גם מספר. לכן TS לא מרשה לגשת לשדות שלא בטוח שקיימים:

❌ T בלי הגבלה

        function getId<T>(item: T): number {
          return item.id;
          // ❌ Property 'id' does not exist
          //    on type 'T'.
        }

✅ T extends HasId

        interface HasId { id: number }

        function getId<T extends HasId>(item: T): number {
          return item.id; // ✅ T surely has id
        }
        getId({ id: 7, name: "Dana" }); // 7
T extends HasId = "T יכול להיות כל טיפוס – בתנאי שיש לו id: number". שדות נוספים (כמו name) מותרים.

Constraints – מה ההגבלה מונעת

        const product = { sku: "A-1", price: 19.9 };

        //    is not assignable to parameter of type 'HasId'.
        //    Property 'id' is missing in type

        //    but required in type 'HasId'.

    T extends { id: number }

Repository<T extends HasId> – מחלקה גנרית עם constraint

  • class Queue<T> – מבנה נתונים לכל טיפוס
  • T extends HasId – הגבלה: רק טיפוסים עם id
  • בזכות ה-constraint מותר entity.id
  • Partial<T> – משתלב עם utility types: עדכון חלקי
  • שימושי ל: test data builders, caches, clients
      interface HasId { id: number }

      class Repository<T extends HasId> {
        private store = new Map<number, T>();

        save(entity: T): void {
          this.store.set(entity.id, entity); // OK: constraint
        }
        findById(id: number): T | undefined {
          return this.store.get(id);
        }
        findAll(): T[] {
          return [...this.store.values()];
        }
        update(id: number, changes: Partial<T>): T | undefined {
          const existing = this.store.get(id);
          if (!existing) return undefined;
          const updated = { ...existing, ...changes };
          this.store.set(id, updated);
          return updated;
        }
      }

keyof ו-T[K] – הטיפוסים של שמות השדות

  • keyof T – איחוד של כל שמות השדות של T
  • T[K] – הטיפוס של השדה K בתוך T ("indexed access")
  • טעות בשם שדה = שגיאת קומפילציה, לא באג בבדיקה

          obj: T,

          return obj[key];

        function pluck<T, K extends keyof T>(
          items: T[],
          key: K,
        ): T[K][] {
          return items.map((item) => item[key]);
        }

          { id: 1, name: "Dana", role: "admin" },

        class TestDataBuilder<T extends object> {
          private overrides: Partial<T> = {};

          constructor(private readonly defaults: T) {}

          with<K extends keyof T>(key: K, value: T[K]): this {
            this.overrides[key] = value;
            return this;
          }

          build(): T {
            return { ...this.defaults, ...this.overrides };
          }
        }

          .build();

          if (path === "/users") {
            return { status: 200, body: this.users as T };
          }
          const match = path.match(/^\/users\/(\d+)$/);
          if (match) {

            return user
              ? { status: 200, body: user as T }
              : { status: 404, body: { error: "not found" } as T };
          }
          return { status: 404, body: {} as T };
        }

      abstract class BaseApiTest {
        constructor(
          public readonly name: string,
          protected client: HttpClientMock,
        ) {}

        protected abstract test(): void;

        run(): TestResult {
          try {
            this.test();
            return { name: this.name, status: "passed" };
          } catch (err) {
            return { name: this.name, status: "failed",
                     reason: (err as Error).message };
          }
        }
      }

שלב 6: Polymorphism – TestSuite

  • הסוויטה מחזיקה BaseApiTest[] – לא יודעת איזה סוג בדיקה היא מריצה

      class TestSuite {
        private tests: BaseApiTest[] = [];

        add(...tests: BaseApiTest[]): this {
          this.tests.push(...tests);
          return this; // enables chaining
        }

        run(): void {
          const results = this.tests.map((t) => t.run());
          for (const r of results) {
            console.log(r.status === "passed"
              ? `✔ ${r.name}` : `✘ ${r.name} -> ${r.reason}`);
          }
          const passed = results.filter((r) => r.status === "passed").length;
          console.log(`\n${passed}/${results.length} passed`);
        }
      }
