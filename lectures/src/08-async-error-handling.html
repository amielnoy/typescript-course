שלושת המצבים של Promise

pendingממתין – עדיין אין תשובה
←
fulfilled ✅הצליח – יש ערך
resolve(value)
או
rejected ❌נכשל – יש שגיאה
reject(error)
מצבמה זה אומרמי מטפל בו
pendingהבקשה נשלחה, מחכים לתשובה– (עוד אין מה לטפל)
fulfilledהפעולה הצליחה, יש תוצאה.then(value => ...)
rejectedהפעולה נכשלה, יש Error.catch(err => ...)
  • Promise מתחיל תמיד ב-pending, ועובר פעם אחת בלבד למצב סופי (settled) – ולא משתנה יותר
  • אנלוגיה: מספר מעקב של משלוח – החבילה עוד לא אצלכם, אבל יש "הבטחה" שתגיע (או הודעה שנכשלה)

יצירת Promise – new Promise ו-sleep

  • new Promise((resolve, reject) => ...) – שני "כפתורים": resolve ← fulfilled, reject ← rejected
  • Promise<User> = "בעתיד יהיה כאן User" · Promise<void> = "סיימתי"
  • sleep עוטף את setTimeout ב-Promise – כדי לדמות שרת איטי
        Promise { <pending> }
        Promise { { id: 1, name: 'User1' } }
בפועל fetch ו-Playwright כבר מחזירים Promise – כאן זה כדי להבין מה קורה בפנים
      type User = { id: number; name: string };
      function sleep(ms: number): Promise<void> {
        return new Promise((resolve) => setTimeout(resolve, ms));
      }
      function fetchUserMock(id: number): Promise<User> {
        return new Promise((resolve, reject) => {
          setTimeout(() => {
            if (id > 0) resolve({ id, name: `User${id}` });
            else reject(new Error(`Invalid id ${id}`));
          }, 100); // מדמה שרת שעונה אחרי 100ms
        });
      }

      const p = fetchUserMock(1);
      console.log(p);                  // מיד
      p.then(() => console.log(p));    // אחרי 100ms

then / catch / finally

  • then – כשהצליח
  • catch – כשנכשל
  • finally – תמיד (ניקוי)
  • מה שמחזירים מ-then עובר ל-then הבא
  • שימו לב לסדר ההדפסות!
        1. before
        2. after – runs BEFORE the promise resolves!
        3. got user: User1
        4. 10
        5. always
      
      console.log("1. before");
      fetchUserMock(1)
        .then((user) => {
          console.log("3. got user:", user.name);
          return user.id * 10; // עובר ל-then הבא
        })
        .then((value) => console.log("4.", value))
        .catch((err: Error) => console.log("error:", err.message))
        .finally(() => console.log("5. always"));
      console.log("2. after – runs BEFORE the promise resolves!");

שרשור: מחזירים Promise מתוך then

  • מחזירים ערך מ-then ← הוא עובר ל-then הבא
  • מחזירים Promise ← ה-then הבא מחכה שהוא יסתיים
  • כך בונים תרחיש: login ← profile ← בדיקה

        profile: Dana
שכחתם return? ה-then הבא לא מחכה ומקבל undefined
      function login(user: string): Promise<string> {
        return sleep(100).then(() => `token-${user}`);
      }
      function getProfile(token: string): Promise<User> {
        return sleep(100).then(() => ({ id: 1, name: "Dana" }));
      }

      login("dana")
        .then((token) => {

          return getProfile(token); // ה-then הבא יחכה לו

        .then((profile) => console.log("profile:", profile.name))

כולן מקבלות מערך של Promises ומחזירות Promise אחד – שאפשר לעשות לו then או await

Promise.all ו-Promise.allSettled

  • all: הכול יחד – ⏱️ 101ms ולא 300ms. התוצאות באותו סדר כמו הקלט
  • all: אחת נכשלה ← הכול נכשל מיד – fail fast
  • allSettled: אף פעם לא נכשל; r.status ← value / reason
  • מושלם ל-QA: רואים את כל הכישלונות, לא רק את הראשון
        User1, User2, User3 in 101ms
        rejected: Invalid id -5
        id 1: ✅ User1
        id -2: ❌ Invalid id -2
        id 3: ✅ User3
      
      const start = Date.now();
      Promise.all([1, 2, 3].map(fetchUserMock)).then((users) => {
        const names = users.map((u) => u.name).join(", ");
        console.log(`${names} in ${Date.now() - start}ms`);
      });
      Promise.all([fetchUserMock(1), fetchUserMock(-5)])
        .catch((err: Error) => console.log("rejected:", err.message));

      const ids = [1, -2, 3];
      Promise.allSettled(ids.map(fetchUserMock)).then((results) => {
        results.forEach((r, i) => {
          if (r.status === "fulfilled") {
            console.log(`id ${ids[i]}: ✅ ${r.value.name}`);
          } else {
            console.log(`id ${ids[i]}: ❌ ${r.reason.message}`);
          }
        });
      });

Promise.race ו-Promise.any – מי ראשון?

  • race – הראשון שמסתיים קובע (הצלחה או כישלון)
  • שימוש קלאסי: timeout – "אם הדף לא נטען תוך 100ms, תיכשל"
  • any – הראשון שמצליח; מתעלם מכישלונות
        race winner: fast server
        any: mirror 2
        race rejected: Timeout after 100ms
      
      Promise.race([
        sleep(50).then(() => "fast server"),
        sleep(500).then(() => "slow server"),
      ]).then((winner) => console.log("race winner:", winner));

      const timeout = sleep(100).then(() => {
        throw new Error("Timeout after 100ms");
      });
      Promise.race([sleep(300).then(() => "page loaded"), timeout])
        .then((v) => console.log(v))
        .catch((err: Error) => console.log("race rejected:", err.message));

      Promise.any([
        Promise.reject(new Error("mirror 1 down")),
        sleep(80).then(() => "mirror 2"),
        sleep(150).then(() => "mirror 3"),
      ]).then((first) => console.log("any:", first));

async / await

אותו Promise – קוד שנקרא כמו רצף רגיל. סדרתי מול מקבילי, ומה קורה כששוכחים await

async / await – אותו דבר, קריא הרבה יותר

עם then

        function profileThen(): Promise<void> {
          return login("dana")
            .then((token) => getProfile(token))
            .then((user) => console.log(user.name))
            .catch((err: Error) => console.log(err.message));
        }

עם async / await

        async function profileAwait(): Promise<void> {
          try {
            const token = await login("dana");
            const user = await getProfile(token);
            console.log(user.name);
          } catch (err) {
            console.log((err as Error).message);
          }
        }
  • async לפני הפונקציה, await לפני כל Promise – והקוד נקרא שורה אחרי שורה
  • שגיאות נתפסות עם try / catch רגיל (חלק 3)
  • מתחת למכסה זה אותו דבר בדיוק – שתי הפונקציות מדפיסות dana
  • כך כתובות כל בדיקות Playwright: await page.goto(...), await page.click(...)

async מחזירה תמיד Promise · await "פותח" אותו

  • async function תמיד מחזירה Promise – גם אם כתבנו return 200
  • לכן הטיפוס: Promise<number> ולא number
  • await מחכה שה-Promise יסתיים ומחזיר את הערך שבתוכו
  • שכחתם await? מקבלים Promise ולא ערך: getUser(5).name ← ❌ TS2339
  • await מותר רק בתוך async – או ב-top-level של מודול ES (בפרויקט שלנו: "type": "module")
        async function getStatus(): Promise<number> {
          return 200; // נעטף אוטומטית ב-Promise
        }

        const p = getStatus();
        console.log(p);
        console.log(await p);

  • מי שקרא לה ממשיך לרוץ (שורה 3) – ומחזיק Promise
  • כדי לחכות לסיום – גם הקורא צריך await (שורה 5)

סדרתי: כשכל שלב תלוי בקודם

  • כל שלב צריך את התוצאה של הקודם – חייבים לחכות
  • כאן: צריך user.id כדי להביא הזמנות

שכחתם await בבדיקה? הבדיקה "עוברת" – בטעות

❌ בלי await

waitFor – לחכות לתנאי במקום sleep (polling)

  • במקום sleep(5000) "ליתר ביטחון": בודקים שוב ושוב עד שהתנאי מתקיים
  • ממשיכים ברגע שמוכן – לא מחכים סתם
  • לא מוכן עד ה-timeout? נכשלים עם הודעה ברורה (ולא נתקעים לנצח)
  • כך עובדים expect.poll וה-auto-waiting של Playwright
        job done after ~404ms
      
      async function waitFor(
        check: () => Promise<boolean>,
        timeoutMs: number,
        intervalMs = 100,
      ): Promise<void> {
        const deadline = Date.now() + timeoutMs;
        while (Date.now() < deadline) {
          if (await check()) return;   // התנאי התקיים
          await sleep(intervalMs);     // מחכים ובודקים שוב
        }
        throw new Error(`Condition not met within ${timeoutMs}ms`);
      }

      // "השרת" מסיים job ברקע אחרי 350ms
      const start = Date.now();
      const isJobDone = async () => Date.now() - start > 350;
      await waitFor(isJobDone, 1000);
      console.log(`job done after ~${Date.now() - start}ms`);

      async function retry<T>(
        fn: () => Promise<T>,
        attempts: number,
        delayMs: number,
      ): Promise<T> {
        let lastError: unknown;
        for (let i = 1; i <= attempts; i++) {
          try {
            return await fn(); // הצליח? יוצאים מיד
          } catch (err) {
            lastError = err;
            const msg = (err as Error).message;
            console.log(`  attempt ${i} failed: ${msg}`);
            if (i < attempts) await sleep(delayMs);
          }
        }
        throw lastError; // כל הניסיונות נכשלו
      }
    
        let calls = 0;
        async function flakyService(): Promise<string> {
          calls++;
          if (calls < 3) {
            throw new Error("503 Service Unavailable");
          }
          return "OK";
        }
        const result = await retry(flakyService, 5, 50);
        console.log("Retry result:", result);
